# 개발 환경 정보 기입란 — 개발 프롬프트 9종 공용 입력

> 개발 프롬프트 9종(`01-runtime.md` ~ `09-eval.md`)이 **공통으로 읽는 단 하나의 입력 파일**임.  
> 프롬프트를 실행하기 **전에** 이 파일을 먼저 채움. 여기가 비면 프롬프트가 시작 지점에서 막힘.

**이 파일이 설계서와 다른 점** — 설계서는 "무엇을 만들 것인가"를 정함.  
이 파일은 **"무엇으로 만들 것인가"**를 정함. 설계서에 없는 값만 여기에 둠.

---

## 1. 쓰는 법

- 이 파일을 복사하지 않고 **여기에 직접 값을 적음**. 프롬프트가 이 경로를 그대로 읽음
- 값을 모르면 빈칸으로 두지 않고 `프로젝트 확정 필요`라고 적음
- 값을 적은 행마다 **정한 사람과 날짜**를 함께 적음. 팀이 정한 값이면 `개발판단`이라고 적음

**차단 규칙** — 어떤 프롬프트를 실행할 때 그 프롬프트가 쓰는 변수가 `프로젝트 확정 필요`로
남아 있으면 프롬프트는 **코드를 만들지 않고 사용자에게 문의함.** 비운 채 진행하지 않음.

**설계서에 있는 값을 여기에 다시 적지 않음** — 모델 벤더·시간 상한·반복 상한·저장소 제품은
설계서가 주인임. 여기에 또 적으면 두 곳이 어긋났을 때 어느 쪽이 진짜인지 모르게 됨.

| 여기에 적는 것 | 설계서가 주인이라 여기에 안 적는 것 |
|---------------|--------------------------------|
| 언어 · 프레임워크 · 디렉터리 · 시험 도구 | 모델 벤더 · 모델명(④ 「사용 모델」) |
| 상태 저장 백엔드 제품 · 배포 런타임 제품 | 시간 상한 · 재시도 횟수 · 반복 상한 · State 필드 이름 · 프로세스별 API 키 이름(③) |
| 환경변수 이름 규격 | 실행환경 묶음(⑦ 물리 배치도) · 저장소 제품과 색인 파라미터(⑤ 3-1) |
| 관측 기록 규격 | 기록 항목 · 재시도 간격 · 상한 · 알림 임계(⑥) · 가릴 필드(⑤ `F-n` · ⑥ 「마스킹」) |

**⑦ 배포는 물리 배치도 1장이 전부임** — 포트 · 비밀값 목록 · 배포 형태 · 규모 상한 ·
저장소 안/밖 배치 · 접속정보는 **설계 범위 밖**이라 어느 설계서도 갖지 않음.
그 값의 주인은 개발 프롬프트임: **포트는 `07-api-ui.md`**, **비밀값 목록과 나머지는
`08-deploy.md`**가 되묻기로 정함. **여기에도 적지 않음**(제품 종류를 고르는 칸만 여기 둠).

**디렉터리 이름은 설계서 ②의 「내부 관계도」 노드 이름과 맞춤.** 다른 이름을 새로 짓지 않음.  
②가 「프로세스 분리표」로 프로세스를 나눴으면 그 경계도 함께 반영함.
**계층 디렉터리는 그 노드 이름 아래에 들어감.** 노드 이름을 계층 이름으로 바꾸지 않음.

계층별로 무엇이 들어가고 어느 프롬프트가 채우는지는 아래와 같음.
이 칸에 값이 있으면 `07-api-ui.md`가 되묻지 않고 **이 이름을 그대로 씀.**

| 계층 | 무엇이 들어가나 | 채우는 프롬프트 |
|------|---------------|---------------|
| `presentation` | 경로 등록 · 요청 응답 형(DTO) · 오류 변환 · 부분 전송 채널 · 상태 확인 | `07-api-ui.md` |
| `application` | 유스케이스 함수 · 검사 훅 · 가리기 훅 · 마감선 · 재진입 조립 | `07-api-ui.md` |
| `domain` | 워크플로우 · 노드 함수 · 상태 타입 · 구조화 출력 스키마 | `06-workflow.md` · `01-runtime.md` |
| `infrastructure` | 바깥 시스템 어댑터 · 지식 검색 · 모델 클라이언트 · 저장 장치 | `04-connector.md` · `03-knowledge.md` · `01-runtime.md` |

**계층을 안 쓰기로 했으면 두 행을 `해당 없음`으로 적음.** 빈칸으로 두면 프롬프트마다 다르게 나눔.
`공통 모듈 위치`와 `공용 도구 계층 위치`는 서비스 바깥의 공용 라이브러리라 이 4층에 안 들어감.

### D-08 상태 저장 · 중간 저장 장치 백엔드

중간 저장 장치 = 흐름이 중간에 끊겨도 이어서 할 수 있게 상태를 저장해 두는 장치임.

**`세션 격리 키 성분`은 ③ 「체크포인트 보존」이, `보관 기간`은 ⑤ 3-3 「보존·삭제」의 체크포인트
행이 소유함**: 여기에 원본을 두지 않고 **인용만** 함. **`저장 등급`과 백엔드 제품은 설계 범위 밖**
(⑦ 배포는 물리 배치도만 그리고 저장 등급을 정하지 않음)이라 **이 절이 주인임**.

| 항목 | 값 | 정한 사람 · 날짜 |
|------|----|----------------|
| 중간 저장 방식 | 데이터베이스 | 사용자 지정 · 2026-08-08 |
| 저장 등급 | 공유 트랜잭션 저장(인스턴스가 여럿이라 단일 노드 저장을 운영 기본값으로 두지 않음) | 이 절 소유(설계 범위 밖) |
| 백엔드 제품 · 버전 | PostgreSQL(최신 안정판) | 사용자 지정(PostgreSQL) |
| 체크포인터 구현체 | LangGraph `AsyncPostgresSaver`. **바꿔 끼울 수 있게 한 겹 감쌈**(개발은 메모리) | 클로니 도출(프레임워크 종속 값이라 이 절 소유) |
| 세션 식별자 문자열 문법 | ③ 「체크포인트 보존」의 `세션 격리 키 성분`을 `:`로 이어 붙임. **성분을 더하거나 빼지 않고 실행 시각을 넣지 않음** | 이 절 소유(문법만) |
| 보관 기간(인용) | ⑤ 3-3 「보존·삭제」의 체크포인트 행에서 읽음. ③의 `스레드 최소 생존 시간`보다 짧게 잡지 않음 | ⑤ 소유 |
| 만료 삭제 작업 | 프레임워크에 만료 기능이 없어 `08-deploy.md` 9단계가 파기 작업을 만듦 | 클로니 도출 |
