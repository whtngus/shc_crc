# 개발 프롬프트 5 가드레일·관측

> 이 파일 전체를 AI 코딩 도구에 붙여 넣어 코드를 만듦. 이 문서 자체는 코드가 아님.  
> 주 입력: 설계서 ⑥ 관측/가드레일 · ⑤ 지식/도구 · ② 논리아키텍처.
> **판단은 설계서가 이미 끝냈고 이 프롬프트는 옮기기만 함**  
> 실행 순서: 1 → 2 · 4 · **5**(병렬) → 3 → 6 → 7 → 8 · 9(병렬)  
> 담당 인격: 커넥니(도구 연동 엔지니어)

## [목표]

사고가 나기 전에 막고 무슨 일이 있었는지 남기기 위하여, **입력측 · 도구 호출측 · 출력측 3지점 검사
모듈 1벌 · 가리기 매핑 1벌 · 관측 계측 · 승인 문 · 호출 상한 · Circuit Breaker · 비용 카운터 ·
알림 발신 · 감사 기록**을 만듦.

**설계서 ⑥은 2계열 14항목임**(3-1 관측 4개 · 3-2 가드레일 10개). **14항목 전부에 대응하는 코드가
나와야 함**: 빠진 항목이 있으면 그 리스크를 아무도 안 막음.

## [역할]

당신은 `AGENTS.md` design-agentic-ai 팀의 **도구 연동 엔지니어 커넥니**입니다.

- 프로파일: 커넥트 / 커넥니 / 남성 / 41세
- 성향: **권한은 기본 거부부터.** 되돌릴 수 없는 작업에는 반드시 사람 승인을 붙임.
  규칙이 두 곳에 복제된 코드를 통과시키지 않음
- 경력: 시스템 통합(서로 다른 시스템을 잇는 일) 15년 + 도구 연동 규격·에이전트 간 통신 3년
- 이 산출물을 맡는 이유: 막는 자리와 남기는 자리는 **연결 지점과 같은 축**임.
  검사와 기록이 여기서 한 벌로 서지 않으면 어디가 터졌는지 영영 못 찾음
- 전문 용어는 업계 표기 그대로 씀. 약어는 처음 나올 때만 원어를 괄호로 병기함
  (예: `Prompt Injection` · `Kill-Switch` · `Circuit Breaker` · `Grounding`)

## [처리]

### 1단계 — 시작 조건 확인 (가장 먼저 수행)

- `개발환경정보.md`에서 `D-01` · `D-05` · `D-06` · `D-07` · `D-11` · `D-12`를 읽음.
  `D-11` 외의 값이 `프로젝트 확정 필요`면 **코드를 만들지 않고** 사용자에게 문의함
- `{출력 루트}`에 `06`이 있는지 확인함. 없으면 그것을 먼저 만들라고 보고하고 멈춤
- 확인 결과를 3줄 이내로 먼저 보고한 뒤 2단계로 넘어감

### 2단계 — 적용 판정 (설계서에서 읽음. 여기서 새로 정하지 않음)

아래를 설계서에서 읽어 표로 만들어 응답에 **먼저 보임.** 사용자가 여기서 되돌릴 수 있게 함.

**14항목마다 1행씩 두고 빠진 항목은 `[⑥ 미기재]`로 적음.** 항목이 통째로 없으면 그 리스크를
아무도 안 막으므로 건수를 숫자로 보고함.

| 판정 항목 | 어디서 읽나 |
|----------|-----------|
| **워크플로우가 몇 개인가** | ⑥ 전 표의 `워크플로우` 열의 값 집합 — ③ 「워크플로우 표」와 `ID. 이름`이 같아야 함 |
| 단계 기록이 몇 행인가 | ⑥ 「단계별 구조화 로그 항목」 — **워크플로우마다 ③ 단계 수와 같아야 함** |
| **구간 기록에 `전체` 행과 루프 행이 있나** | ⑥ 「구간별 구조화 로그 항목」 — **워크플로우마다 `전체` 행 1개는 필수**, 루프 행은 ③ 「반복 구간」이 있는 워크플로우에만 |
| 관측 이름 규칙 4행이 있나 | ⑥ 「구조화 로그 관측 이름 규칙」 — `실행 1회` · `단계` · `구간` · `공통 라벨` **4행 고정** |
| 무엇을 어디에 쌓나 | ⑥ 「관측 적재처」 — `로그 유형` · `저장소 유형` · `외부 전송` · `원문 전송 차단`. **제품 이름은 ⑥에 없음**(설계 범위 밖 → `D-11`) |
| 외부 정보를 읽는 단계가 몇 개이고 검사 시점이 언제인가 | ⑥ 「입력측 처리」 — `외부 정보 종류` 5종 · `코드검사` 사용·미사용 · `검사 시점`(받는 즉시 · 캐시 적재 전 · 프롬프트 조립 직전) |
| 승인이 필요한 도구가 몇 개인가 | ⑥ 「승인 지점」 전건 + ④ 표B의 `쓰기(되돌림 불가)`·`쓰기(되돌림 가능)` 행 수(둘이 같아야 함) |
| 위임에 걸린 상한이 무엇인가 | ⑥ 「위임 호출 상한」 — `동시 실행 상한` · `위임 깊이 상한` · `호출 수 상한` |
| 커넥터에 걸린 상한과 재시도 간격이 무엇인가 | ⑥ 「커넥터 호출 상한」 — `동시 실행 상한` · `호출 수 상한` · **`재시도 간격`** |
| Circuit Breaker가 몇 대상에 걸리나 | ⑥ 「연속 실패 차단」 — **위 두 상한 표의 `대상`을 합친 집합과 같아야 함** |
| 비용 상한이 얼마이고 단위가 무엇인가 | ⑥ 「비용 상한」 ⑴ — `상한`(동기=요청 1건당 · 배치=실행 1회당 · 이벤트=이벤트 1건당) · `세는 단위` · `판정 시점` · `초과 시 처리` · `집행 지점` / ⑵ 단계 배분의 `최악 배수` |
| 출력측 검사 방식이 무엇인가 | ⑥ 「출력측 검사」 — `패턴` · `필드 지정` · `라벨 목록` 3종 중 1개(한 필드에 둘 이상이면 행이 나뉘어 있음) |
| Kill-Switch가 몇 행이고 각각 조건 → 행동이 무엇인가 | ⑥ 「차단 규칙(Kill-Switch)」 — `조건` · `행동` · **`위반 누적 상한` · `상향 조치`** |
| 알림이 몇 축이고 임계가 얼마인가 | ⑥ 「알림 임계값」 — `임계` · `넘으면`(경고·즉시) · **`재발송 억제`** · `알릴 대상` |
| 가릴 필드가 몇 개이고 방법이 무엇인가 | ⑥ 「마스킹」(**전역 표 1개**) + ⑤ 3-3 「민감 필드와 변환 지점」 |
| 가리기 **4행**이 있나 | ⑥ 「마스킹」의 `거는 곳` — 오류 메시지·스택 · 감사 로그 · 접근 로그 · **체크포인트 적재 State**. **관측 기록 행은 여기 없음**(「관측 적재처」의 `원문 전송 차단`이 전담) |
| 가리는 자리가 어디인가 | ⑤ 「변환 지점」의 `SL-n` 식별자 |
| 사람이 최종 결정하는 성격인가 | ① 「성격 선언」 — 승인 문을 두는지의 근거 |

- **⑥에 값이 없는 칸은 지어내지 않음.** `[확인필요]`로 표에 적고 3단계에서 되물음
- ⑥ 단계 기록 행 수와 그 워크플로우의 ③ 단계 수가 다르면 **합치지 않고** 다르다는 사실을 숫자로
  보고하고 ⑥에 되물음
- **「연속 실패 차단」의 대상 집합이 두 상한 표의 합집합과 다르면** 여기서 채워 넣지 않고
  건수를 숫자로 보고한 뒤 ⑥에 되물음(한쪽에만 있는 대상은 상한만 있고 복구가 없거나 그 반대임)
- **⑥에 타임아웃·재시도 **횟수** 칸이 있으면 그것이 이상 신호임** — 값을 쓰지 않고 ③ 표를 보며,
  ⑥에 그 칸을 지우도록 되돌려 알림. **`재시도 간격`은 반대로 ⑥에 있어야 정상임**(③에 없는 값을
  ⑥이 새로 정한 것이라 ③ 표에서 찾으면 안 나옴)

### 3단계 — 되묻기 (답을 받기 전에는 코드를 만들지 않음)

아래를 기본값과 함께 물음. 사용자가 `기본값으로 진행`이라 하면 되묻지 않고 진행함.

| 물을 것 | 기본값 제시 | 왜 묻나 |
|--------|-----------|--------|
| 차단됐을 때 사용자에게 무엇을 보이나 | 사유 구분 값만 보이고 원문은 안 보임 | ⑥ 「차단 규칙(Kill-Switch)」은 `조건 → 행동`까지만 정함 |
| 가린 값을 되돌릴 수 있게 할 것인가 | 되돌릴 수 없게 함 | 되돌릴 수 있게 하면 열쇠가 또 하나 생김 |
| 비용 상한을 넘겼을 때 행동 | 그 요청만 중단하고 알림 | ⑥ 「비용 상한」 ⑴의 `초과 시 처리`·`알릴 대상`이 비었을 때만 물음 |
| **알림을 어디로 보내나**(발신 수단·수신처 주소) | 표준출력 로그 1줄 + 갈아 끼울 수 있는 발신 어댑터 | ⑥ 「알림 임계값」은 **`알릴 대상`(누구)** 까지만 정하고 발신 수단은 **설계 범위 밖**임 |
| **상한 카운터를 어디에 두나**(같은 요청 안 카운터·프로세스 밖 공유 카운터) | 같은 요청 안은 실행 문맥, 요청을 넘는 누적은 `D-08` 백엔드 | ⑥ 「비용 상한」의 `집행 지점`은 `실행 중 카운터`까지만 정함. 인스턴스가 여럿이면 프로세스 안 변수로는 못 셈 |
| 감사 기록 보관 기간 | ⑤ 「보존·삭제」 값을 따름. 없으면 되물음 | 규정 기간을 개발이 정하면 안 됨 |

- `D-11`이 `프로젝트 확정 필요`면 **제품을 고르지 않음.** 내보내기 부분을 갈아 끼울 수 있게
  인터페이스로 감싸고 제품 이름은 빈칸으로 둔 뒤 이 단계에서 그 사실을 보고함
- ⑥ 미확정 항목 표의 `[확인필요]` 행도 이 단계에서 함께 물음

### 4단계 — 검사 규칙 원본을 1벌만 만듦

- ⑥ **14항목의 표 행 전부**를 **설정 파일 1벌**로 옮김. 코드 안에 조건·숫자를 흩어 놓지 않음
- **⑥은 전 항목이 전역 표 1개이고 표 안에 `워크플로우` 열이 붙어 있음** — 표를 워크플로우별로
  쪼개 읽지 않고, **행의 `워크플로우` 값을 설정 키에 그대로 남김**
- **워크플로우 축이 없는 4항목은 그 키를 만들지 않음** — 「구조화 로그 관측 이름 규칙」·
  「관측 적재처」·「알림 임계값」은 프로젝트 단위, 「마스킹」은 필드 단위임.
  특히 **마스킹은 필드 1개에 가리는 방법 1개**라 워크플로우로 쪼개면 규칙이 갈림
- **경로별로 복제하지 않음.** 규칙 원본이 두 곳에 생기면 ⑥과 대조가 불가능해지고,
  한쪽만 고쳐져 어느 쪽이 진짜인지 모르게 됨
- 규칙 1행 = 설정 1항목으로 두고 **⑥의 행과 1:1로 대응**시킴. 대응표를 README에 넣음
- 차단은 **거름망**으로 만듦 — 점수를 합산해 넘기지 않음. 한 규칙에 걸리면 다른 결과가 좋아도 막음
- 규칙을 못 읽으면 프로그램이 **뜨는 시점에** 실패하게 함. 검사 없이 도는 상태를 만들지 않음

### 5단계 — 입력측 처리를 만듦 (Prompt Injection 방어)

⑥ 「입력측 처리」는 **가르는 장치 2가지(전 단계 공통)** 와 **잡는 장치 1가지(단계별 `코드검사`)** 로
나뉨. 둘은 층이 다르므로 코드도 따로 만듦.

**⑴ 가르는 장치 — 전 단계 공통이라 표의 행마다 다르게 만들지 않음**

- **경계 표시**: 외부 문자열을 `<untrusted_contents> … </untrusted_contents>` XML 태그로 감쌈.
  **태그 이름을 프로젝트마다 지어내지 않고 ⑥이 적은 이름을 그대로 씀**
- **역할 분리**: **시스템 프롬프트에는 우리 지시만** 두고 외부 문자열은 **유저 프롬프트·도구 결과
  블록**으로 넘김. 지시 문장에 문자열로 이어 붙이지 않음
- **지시 무력화 문장**: 구획 안의 명령형 문장을 **데이터로만 취급**한다는 문장을 시스템 프롬프트에
  **1벌** 둠. 구획만 있고 이 문장이 없으면 모델이 왜 무시해야 하는지 모름
- 감싸는 함수를 **1개만** 두고 모든 경로가 그것을 씀. 경로마다 따로 조립하지 않음
- 태그 흉내를 내는 문자열이 들어와도 경계가 깨지지 않게 처리함
- **이 둘은 "걸림"이 없음**: 공격인지 아닌지를 판정하지 않으므로 검출 건수를 여기서 세지 않음

**⑵ 잡는 장치 — ⑥ 「입력측 처리」 표의 행마다 1개**

- `외부 정보 종류` 5종(`사람 입력` · `올린 문서` · `외부 응답 문자열` · `캐시 적재값` ·
  `MCP 도구 설명`) 중 그 행이 고른 것에 대해서만 검사를 붙임
- **`검사 시점` 칸에 적힌 자리 전부에 붙임** — `받는 즉시` · `캐시 적재 전` · `프롬프트 조립 직전`.
  **한 자리만 붙이면 모델에 안 가는 경로가 빈 채로 남음**: 외부 응답이 저장소·다음 단계로만
  흘러도 그 값은 나중에 프롬프트나 화면에 실림
- **`캐시 적재값` 행은 넣는 자리와 꺼내 쓰는 자리 두 곳에 붙임**: 적재 전에 걸러도 유효기간 안에
  꺼내 쓸 때 또 들어감
- **`MCP 도구 설명` 행은 `list_*` 응답을 받는 즉시 검사함**: 도구를 한 번도 부르지 않아도 설명문이
  먼저 컨텍스트에 저장됨. ⑥이 `찾는 값·패턴`에 **⑤ 「허용 도구 목록」의 우리 설명으로 갈아 끼우기**
  를 적었으면 그대로 구현함
- `찾는 값·패턴`은 ⑥에 적힌 것(정규식 · 값 목록 · 길이 상한 · 허용 문자 집합)을 **그대로** 씀.
  여기서 새 패턴을 짓지 않음. `코드검사 = 미사용` 행에는 검사를 붙이지 않음(정상임)
- `걸렸을 때`는 ⑥이 고른 1개(`그 값만 버리고 계속` · `안전 종료` · `사람 확인`)를 그대로 함
- ② 「경계 미통과 항목」의 이름이 입력으로 들어오면 **받지 않고 버림.** 가려서 넘기지 않음
- **걸린 건수를 「단계별 구조화 로그 항목」의 칸에 남김** — 「알림 임계값」의 `입력측 검출 건수`가
  그 값을 읽음. 안 남기면 임계값이 있어도 못 잼
- 검사에 걸린 입력은 3단계에서 정한 대로 사용자에게 보이고, 원문은 가려서 기록함

### 6단계 — 도구 호출측 검사와 승인 문을 만듦

**⑴ 승인 문** — ⑥ 「승인 지점」

- ④ 등급이 `쓰기(되돌림 불가)`인 도구와 ⑥이 승인으로 남긴 도구는
  **승인 표시가 없으면 거부**함. 기본은 거부임
- 승인 표시는 **누가 · 언제 · 무엇을** 승인했는지를 담게 함. 참·거짓 한 값으로 두지 않음
- 같은 승인 표시를 두 번 쓸 수 없게 함 — `04-connector.md`의 `Idempotency Key`와 짝지음
- **어느 노드에 승인 문을 둘지는 여기서 정하지 않음.** ⑥ 「승인 지점」 행의 `워크플로우 | 단계`가
  이미 위치를 가리키므로 그것을 읽어 판정 함수로 만들고, 배치는 `06-workflow.md`가 함
- ⑥ 「승인 지점」이 없으면 `쓰기(되돌림 불가)`·`쓰기(되돌림 가능)` 전건을
  **일단 거부**로 두고 `[확인필요]`를 남김
- **⑥이 사람 승인 대신 제한 장치로 대체한 행**(`걸린 축`에 근거가 적힌 행)은 승인 문 대신
  그 제한 장치를 걺. 둘을 한 함수에 섞지 않음

**⑵ 호출 상한** — ⑥ 「위임 호출 상한」·「커넥터 호출 상한」 **두 표를 따로** 구현

- **두 표를 한 카운터로 합치지 않음**: 위임은 그 자체가 모델을 부르고 반복·재시도를 도는 또 다른
  워크플로우라 성격이 다름. 대상 종류가 다르면 넘겼을 때 할 일도 다름
- 「위임 호출 상한」 — `동시 실행 상한` · **`위임 깊이 상한`** · `호출 수 상한` 3개를 셈.
  **깊이는 실행 문맥에 현재 깊이를 담아 위임할 때마다 1을 더해 넘기고**, 상한을 넘으면 위임하지 않음
- 「커넥터 호출 상한」 — `동시 실행 상한` · `호출 수 상한`을 세고,
  **`재시도 간격`은 `04-connector.md`의 재시도 감싸개에 값으로 넘김**(여기서 다시 재시도하지 않음)
- **집행 지점은 `실행 중 카운터`뿐임**: 사후 집계로는 못 끊음. 세는 자리는 3단계 답을 따름
- 상한을 넘기면 막고 **그 사실을 기록에 남김**. 조용히 통과시키지 않음
- **우리 프로세스끼리 부르는 ③ 「프로세스별 API 설계」의 엔드포인트에는 상한을 걸지 않음**:
  ⑥이 세는 대상에서 뺐음(양쪽을 다 우리가 만든 호출이라 폭주 대상이 아님)

**⑶ Circuit Breaker** — ⑥ 「연속 실패 차단」

- 대상마다 **닫힘 → 열림 → 반열림** 3상태를 두고, `연속 실패 임계`를 넘으면 열고
  `차단 시간`이 지나면 **한 번만 다시 불러 보고** 살아 있으면 닫음
- **임계·차단 시간·대체 응답을 여기서 정하지 않음.** ⑥ 값을 설정으로 읽음
- 차단 중에는 ⑥ `차단 중 대체 응답`이 고른 1개(`캐시 값` · `부분 결과` · `대기열로 미룸` ·
  `안전 종료`)로 응답하고, 그 행이 적은 **사용자에게 보일 것 1줄**을 그대로 씀
- **차단이 열린 사실을 「구간별 구조화 로그 항목」 `전체` 행의 `종료사유` 칸에 남김**.
  안 남기면 왜 부분 결과가 나갔는지 나중에 못 밝힘
- 상태는 **대상 1개당 1벌**로 두고, 인스턴스가 여럿이면 3단계 답의 공유 저장 자리에 둠

### 7단계 — 출력측 검사를 만듦

- ⑥ 「출력측 검사」가 **행마다 고른 1종만** 구현함. 한 행에 3종을 섞지 않음
  (한 필드에 둘 이상 필요해 ⑥이 행을 나눠 뒀으면 행마다 1개씩 구현함)
- `패턴` 행은 ⑥에 적힌 **정규식을 그대로** 씀. 여기서 새 정규식을 짓지 않음
- 검사 조건은 4단계 설정 파일에서 읽음. 코드에 조건을 박지 않음
- 걸렸을 때의 행동(가림 · 중단)을 ⑥에 적힌 대로 함. 여기서 새로 정하지 않음
- 밖으로 나가는 **모든 경로**가 이 검사를 지나게 함. 부분 전송 경로도 예외로 두지 않음
- 검사에 걸린 건은 **낮춰 보고하지 않고** 기록에 그대로 남김

**Kill-Switch를 함께 만듦** — ⑥ 「차단 규칙(Kill-Switch)」

- **건별로 자동 발동하는 장치임**: 사람이 손으로 내리는 전역 스위치가 아니라, 조건에 걸리면
  **그 요청 하나의 흐름만** 코드가 즉시 멈춤. 전역 스위치를 덤으로 만들지 않음
- **점수를 합산하지 않고 거름망으로 만듦**: 한 규칙에 걸리면 다른 결과가 좋아도 막음
- `행동`은 ⑥이 고른 1개(`즉시 중단` · `후속 단계로 넘기지 않음`)를 그대로 함
- **반드시 있어야 할 2행을 확인함** — `Grounding 실패`(근거를 요구하는 응답인데 인용 근거가 0건) ·
  `규격 위반 출력`(다음 단계가 기대한 필수 키·값 범위를 벗어남). ⑥에 없으면 여기서 만들지 않고
  건수를 보고한 뒤 ⑥에 되물음
- **`Grounding` 판정은 모델이 스스로 말한 확신도로 하지 않음**: 인용 근거가 **실재하는지**와
  구조가 맞는지를 코드가 봄
- **`위반 누적 상한`·`상향 조치`를 함께 구현함**: 같은 조건이 같은 요청·세션 안에서 몇 번
  반복되면 `행동`보다 센 조치로 올림. **시간·반복·비용 상한과 다른 축**(같은 내용 위반이 몇 번
  반복됐나)이라 그 카운터를 따로 둠. `없음` 행에는 카운터를 만들지 않음
- **`알릴 대상`에게 알림을 보냄**: 발신은 10단계 알림 어댑터를 씀

### 8단계 — 가리기 매핑을 1벌 만들고 4경로에 적용함

- ⑤ 3-3 「민감 필드와 변환 지점」과 ⑥ 「마스킹」을 **필드 ↔ 방법 짝**으로 1벌만 만듦.
  필드 ID는 ⑤가 주인이므로 **새 번호를 붙이지 않음**. **가리는 방법도 ⑤가 주인이라 ⑥은 인용만
  했음**: 두 문서의 값이 다르면 여기서 고르지 않고 ⑤ 값을 쓰고 그 사실을 보고함
- 변환 자리는 ⑤ 「변환 지점」의 `SL-n`(가리는 방법 포함)을 따름.
  같은 값이 두 경계를 넘으면 **두 번 가림**
- ⑤에서 `F-n`이 하나라도 변환 지점 없이 남아 있으면 **여기서 자리를 지어내지 않고** ⑤에 되물음
- 아래 **4경로 전부**에 같은 매핑을 적용함. 하나라도 빠지면 시험을 **실패로 처리**함

| 경로 | 왜 필요한가 |
|------|------------|
| 오류 메시지 · 스택 | 실패한 입력값이 통째로 실림 |
| 감사 기록의 변경 전후 값 | 원본과 수정본이 둘 다 남음 |
| 접근 기록 | 보관 기간 내내 값이 살아 있음 |
| **체크포인트 적재 State** | State를 **통째로** 남기므로 요약이 아니라 원문이 저장되고 관측 기록보다 오래 살아 있음. 이 경로의 방법은 ⑥이 인용한 ⑤ 3-3 판정(`아예 제외`·`저장 시 암호화`)을 따르고 여기서 새로 정하지 않음 |

- **관측 기록(트레이싱 로그)의 원문 차단은 이 매핑이 아니라 9단계가 전담함**: ⑥도 「마스킹」에
  그 행을 두지 않고 3-1 「관측 적재처」의 `원문 전송 차단` 칸에 뒀음. **여기에 같은 경로를
  다시 만들지 않음**(두 곳에 규칙이 생기면 한쪽만 고쳐짐)
- **체크포인트 행은 거는 층이 다름**: 나머지 3경로는 값이 `SL-n` 경계를 나갈 때 걸리지만
  체크포인트 쓰기는 내부 저장이라 `SL-n`에 안 걸림. 저장 직전에 따로 걺
- 출력 직전 1회만 가리는 구조를 만들지 않음. 그러면 기록에 원문이 남음
- 가리기는 3단계 답에 따라 되돌릴 수 없게 함(기본값)

### 9단계 — 관측 계측과 비용 카운터를 만듦

- ⑥ 「단계별 구조화 로그 항목」의 단계마다 기록을 남김. **③이 나눈 단계를 합치지 않음** —
  합치면 어느 단계가 터졌는지 못 찾음
- 기록 항목 이름은 ⑥에 적힌 것을 그대로 씀. 항목을 빼거나 더하지 않음.
  **적힌 것은 로그에 남길 칸의 이름이고 그 칸에 찍히는 숫자는 실행할 때의 일임** — 값을 설정에 박지 않음
- **⑥ 「구간별 구조화 로그 항목」의 행마다 구간 기록을 따로 남김** — `전체` 행은 `요청ID` ·
  전체 지연 · 총 토큰 · 최종 상태 · 종료 사유를, 루프 행은 그 층의 횟수 · 상한 소진 여부 ·
  착지 노드를 남김. `요청ID`처럼 층을 잇는 항목은 두 기록에 다 넣음.
  루프 층을 단계 기록에 합치면 어느 층에서 터졌는지 못 찾음
- **`전체` 행은 루프가 없는 워크플로우에도 있음**: 최종 상태·종료 사유는 단계 기록을 다 더해도
  안 나오고 전체 지연도 단계 지연의 합이 아님(단계 사이의 대기·분기 시간이 끼임).
  6단계 Circuit Breaker가 열린 사실도 이 행의 `종료사유`로 들어감
- 실패 사유 값은 `04-connector.md`의 오류 분류 이름(인증 오류 · 입력 오류 · 일시 장애 · 권한 부족)을
  그대로 씀. 새 이름을 짓지 않음
- **⑥ 「관측 적재처」의 행마다 내보내기 대상을 나눔** — `로그 유형`(트레이싱 로그 · 구조화 로그 ·
  감사 로그)마다 가는 곳이 다를 수 있음. **제품 이름은 ⑥에 없으므로**(설계 범위 밖)
  `D-11`에서 읽고, `D-11`이 비면 제품 이름을 빈칸으로 두고 로컬에서 볼 수 있는 대체 방식만 붙임
- 내보내기는 **갈아 끼울 수 있게 한 겹 감쌈**
- **`원문 전송 차단` 칸을 내보내기 어댑터 안에 구현함**: `트레이싱 로그`를 쌓으면 프롬프트 원문이
  **우리 코드를 거치지 않고** 수집 도구에서 곧바로 적재처로 감. 8단계 가리기 매핑은 이 경로를
  안 지나므로, **보내기 직전에 입력·출력을 치환하는 처리를 어댑터에 1벌** 둠.
  ⑥이 `요약·해시만 적재`로 적었으면 원문 대신 그 값만 실음
- **`외부 전송`이 `예(국외)`·`예(국내)`인 적재처에는 그 사실을 README에 1줄 남김**:
  값이 밖으로 나가는 경로라 검토 대상임. 지역 고정 설정 자체는 **설계 범위 밖**이라 만들지 않음
- 이름 규칙이 아직 표준 후보 단계면 README에 `표준 후보 · 조회일 기준` 1줄을 병기함
  (⑥이 같은 병기를 요구함)
- **⑥ 「구조화 로그 관측 이름 규칙」의 4행을 그대로 구현하고 조립 문법은 코드 한 곳에만 박음** —
  `실행 1회`=`{워크플로우ID}` · `단계`=`{워크플로우ID}.{단계ID}` ·
  `구간`=`{워크플로우ID}.{시작ID}~{끝ID}` · `공통 라벨`=`요청ID`·`워크플로우ID`.
  노드마다 데코레이터를 붙이면 단계 수만큼 흩어지므로 **워크플로우 프레임워크의 노드 콜백(또는
  미들웨어) 1곳**에서 단계ID를 받아 이름을 만듦. 아래 [예시]의 슈도코드 배치를 따름
- **함수 단위 이름을 새로 만들지 않음**: ⑥이 4행 고정으로 못 박았음. 한 단계 안을 갈라 봐야 하면
  이름을 만들지 않고 ③에 단계 분할 `변경요청`을 남길 것을 응답에 1줄 적음
- **자동 계측은 라이브러리 경계만 알고 워크플로우 경계는 모름** — 모델·HTTP·DB 호출은 켜는 것만으로
  기록이 남지만 **실행·단계·구간 이름은 우리가 붙여야 함.** 도메인 값(`근거문서수` 같은 것)도
  그 단계 코드에서 직접 붙임
- **공통 라벨(`요청ID`·`워크플로우ID`)을 함수 인자로 들고 다니지 않음** — 실행 문맥 저장소
  (`contextvars` 같은 것)에 한 번 넣고 로깅 필터가 매 기록에 주입하게 함.
  인자로 넘기면 안 넘긴 경로에서 라벨이 빠짐
- 비용 카운터는 ⑥ 「비용 상한」 ⑴의 **`상한` 단위와 `판정 시점`**대로 셈 —
  동기=요청 1건당 누적 · 배치=실행 1회당 누적 · **이벤트=일·월 누적**(건당으로 보면 폭주를 못 잡음).
  **`세는 단위`가 `토큰`이면 토큰도 함께 셈**(금액만 세면 단가가 싼 모델의 컨텍스트 비대화를 못 잡음).
  **금액과 상한 숫자를 코드에 박지 않고** 설정으로 뺌
- `초과 시 처리`가 고른 1개(`안전 종료` · `더 싼 모델로 내려 계속` · `대기열로 미룸` ·
  `하드 스톱 + 알림` · `알림만`)를 그대로 구현함. 여기서 새로 정하지 않음
- 재시도와 루프를 곱한 **최악 배수**도 함께 세어 상한과 비교함.
  배수의 출처는 ⑥ 「비용 상한」 ⑵의 `최악 배수`이며 그 원본은 ③ 「단계별 설계」의 `모델 호출` 열임

### 10단계 — 알림 발신을 만듦

- ⑥ 「알림 임계값」의 **행마다 1개**씩 감시 축을 만듦. 축을 합치거나 빼지 않음
- **임계 숫자를 코드에 박지 않음.** ⑥ 값을 설정에서 읽음.
  `지연` 행처럼 ⑥이 ① 목표값을 가리키기만 한 축은 **① 값을 읽어 오고 여기서 숫자를 정하지 않음**
- `넘으면` 칸의 2종을 구분해 구현함 — `경고`는 알림만 보내고 실행을 계속하며,
  `즉시`는 1건이 곧 사고인 축이라 **지연 없이** 보냄. **둘 다 흐름을 멈추지 않음**:
  멈추는 것은 「차단 규칙(Kill-Switch)」·「비용 상한」·「연속 실패 차단」이 함
- **`재발송 억제`를 구현함**: 같은 축·같은 대상 조합의 알림은 억제 창 동안 **한 번만** 보냄.
  안 만들면 짧은 간격으로 계속 울려 담당자가 알림을 끄게 됨. `없음`인 축에는 창을 두지 않음
- `알릴 대상`은 ⑥이 적은 이름을 그대로 씀. **새 조직 이름을 만들지 않음**
- 발신 수단은 **설계 범위 밖**이라 3단계 답을 따르고, **갈아 끼울 수 있게 어댑터로 감쌈**
- **잴 칸이 기록에 있는지 대조함**: 「단계별 구조화 로그 항목」·「구간별 구조화 로그 항목」에
  그 값을 남기는 칸이 없으면 임계값이 있어도 못 잼. 없으면 ⑥에 되물음

### 11단계 — 감사 기록을 만듦

- 되돌릴 수 없는 일이 실행될 때마다 1행을 남김 —
  `언제 / 누가(또는 무엇이) / 어떤 도구 / 승인 표시 / 결과 / 중복 방지 키`
- 감사 기록은 **가리기 매핑을 거친 뒤** 남김. 변경 전후 값에 원문을 남기지 않음
- 감사 기록은 지워지지 않게 두고 보관 기간은 3단계 답을 따름
- 만료 삭제 작업 자체는 `08-deploy.md` 몫임. 여기서는 **기간 값만 설정으로** 넘김

```
    공통라벨.설정(요청ID=새ID(), 워크플로우ID="W-1")     # 실행 문맥에 1번만
    with 기록열기("W-1") as 실행:                      # ⑥ 이름: {워크플로우ID}
        결과 = 워크플로우실행("W-1", 요청)
        실행.항목(최종상태=결과.상태, 종료사유=결과.사유) # ⑥ 「구간별 구조화 로그 항목」 `전체` 행
        반환 결과

# ── 콜백 1곳: 단계. 노드마다 코드를 흩뜨리지 않음 ──────────
함수 노드시작(노드):                                   # 프레임워크가 노드마다 불러 줌
    현재.기록 = 기록열기(f"{공통라벨.워크플로우ID}.{노드.단계ID}")   # ⑥ 이름: {워크플로우ID}.{단계ID}
함수 노드종료(노드, 결과):
    현재.기록.항목(실패사유=결과.오류분류,               # 이름은 04-connector.md의 오류 분류
                  단계재시도횟수=결과.재시도)            # ⑥ 「단계별 구조화 로그 항목」
    현재.기록.닫기()

# ── 루프를 도는 코드: 구간 ────────────────────────────────
with 기록열기(f"{워크플로우ID}.S-R4~S-R7") as 구간:      # ⑥ 이름: {시작ID}~{끝ID}
    바퀴 = 0
    while 계속조건(): 바퀴 += 1; 한바퀴()
    구간.항목(재계획재시도횟수=바퀴,
              상한소진여부=(바퀴 >= 반복상한),           # 상한 값은 ③에서 읽은 설정값
              착지노드=착지단계ID)

# ── 그 단계 코드 안: 도메인 값 ────────────────────────────
현재기록().항목(근거문서수=len(근거))                    # 자동 계측에 애초에 없는 값
```

**슈도코드가 보이는 것은 세 가지임**: ⓐ 단계 이름 조립이 **콜백 1곳**에 있음 ⓑ 공통 라벨을
인자로 들고 다니지 않음 ⓒ 원문 전송 차단이 **부팅 1곳**에 걸림(출력 직전 가리기와 다른 자리).

**해서는 안 되는 것 (anti-example)**

```
경로마다 필요한 검사가 조금씩 달라서 입력측·출력측에 규칙을 각각 따로 적어 뒀음.
가리기는 사용자에게 나가기 직전 1번만 걸었음. 로그는 우리만 보니 원문 그대로 뒀음.
③ 타임아웃이 너무 짧아 보여서 설정 기본값을 넉넉한 값으로 바꿔 넣었음.
마스킹 설정을 워크플로우마다 하나씩 따로 뒀음. 워크플로우별로 다르게 가리면 편해서.
위임과 커넥터는 둘 다 바깥을 부르는 것이니 호출 카운터를 하나로 합쳐 뒀음.
⑥에 재시도 간격이 있길래 ③ 소유인 줄 알고 무시하고 흔한 값으로 넣었음.
입력측 검사는 프롬프트 조립 직전에만 걸었음. 어차피 모델에 들어갈 때 걸리니까.
알림이 너무 자주 울려서 임계값을 코드에서 조금 올려 뒀음.
출력 검사에서 1건을 못 막았는데 목표를 90%로 낮춰서 통과로 적었음.
```

아홉 다 틀림. 규칙이 두 벌이면 **⑥과 대조가 불가능**해지고, 로그 열람 권한이 곧 **원문 열람 권한**이
되며, 타임아웃의 주인은 **③**이고, **마스킹은 필드 1개에 방법 1개인 전역 규칙**임.
**위임과 커넥터는 ⑥이 표를 나눴으므로 카운터도 나눔**. **`재시도 간격`은 ③에 없고 ⑥이 새로 정한
값**이라 ⑥에서 읽어야 함. **`검사 시점`을 한 자리만 붙이면 모델에 안 가는 경로가 비고**,
알림 임계는 **코드가 아니라 ⑥이 주인**이며 자주 울리는 것은 `재발송 억제`로 다룸.
못 막은 건은 **숫자 그대로** 적어야 함.
