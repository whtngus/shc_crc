[목표]
아키텍처 설계서 7종의 값을 실행 가능한 코드로 옮기기 위하여, 사용자가 지정한 기획 산출물ㆍ설계서
경로와 개발 환경 정보를 입력으로 개발 프롬프트 9종을 정해진 순서(파이프라인형 + 일부 병렬)로 호출해
코드ㆍ시험ㆍREADME를 생성하는 유저스코프 스킬 실행

[역할]
design-agentic-ai 팀의 오케스트레이터 클로니가 프롬프트별 담당자에게 실제 위임하여 진행함.
담당자 전환은 문서상 서술로 끝내지 않고 `Agent` 도구로 서브에이전트를 실제 호출함(패턴은 문서상
선언이 아니라 실제 Agent 호출로 실행함 · 정직한 보고 규칙). **담당 인격은 두 겹으로 실림** —
`subagent_type`에 `.claude/agents/`의 에이전트명(`flonie`ㆍ`jisikni`ㆍ`connectni`ㆍ`stackni`ㆍ`opsni`)을
지정해 팀원 정의를 싣고, 개발 프롬프트 9종 각각의 머리말 `> 담당 인격:` 행과 `[역할]` 절이 산출물별
세부 인격을 더함. 에이전트명이 실행 환경에 없으면 `general-purpose`로 대체 호출하되 인격은 프롬프트
파일이 실어 옴. 담당 배정표ㆍ판정 근거ㆍ협업 패턴 분류는 [처리] 0단계에 둠.

[맥락]
- 내 상황: `{스킬 디렉토리}/prompts/` 개발 프롬프트 9종을 매 프로젝트마다 손으로 `개발환경정보.md`를 채우고
  순서를 기억해 하나씩 AI 코딩 도구에 복붙하던 방식을 스킬로 패키징해 재사용하고 싶음
- 결과물 독자: 설계서 7종을 이미 만들어 둔 개발자ㆍ아키텍트 — 이 스킬로 코드 생성을 시작함
- 이 스킬이 하지 않는 일: 설계서 7종을 만드는 일(`design-architecture` 스킬 소관) ㆍ 개발 프롬프트
  9종의 판단 기준을 새로 정하는 일(설계서와 `개발환경정보.md`가 이미 판단을 끝냄). 위임은 "전략을
  새로 정하는 일"이 아니라 "이미 정해진 값을 코드로 구현하는 일"에 한정됨
- 용어: `대상 프로젝트 루트`는 이 스킬을 호출한 시점의 현재 작업 디렉토리(cwd)를 가리킴. 이 값은
  사용자에게 묻지 않고 그대로 씀
- 비용 특성: 개발 프롬프트 9종은 파일당 100줄을 넘는 경우가 많음. 매 위임마다 파일 전문을
  오케스트레이터의 Agent 호출 인자 안에 다시 옮겨 적으면 같은 내용이 오케스트레이터ㆍ서브에이전트
  두 컨텍스트에 이중으로 쌓여 단계가 진행될수록 비용이 누적됨 — [처리]에서 경로만 전달하고
  서브에이전트가 직접 Read하게 하여 이중 적재를 막음
- 도구 제약: 이 스킬(오케스트레이터)은 Bashㆍ PowerShellㆍMCP 도구를 쓰지 않음. 프롬프트가 요구하는
  **시험 실행**과 **context7 MCP 조회**는 코드를 만드는 서브에이전트 쪽에서 일어나며,
  오케스트레이터는 그 결과 보고를 받아 취합함. 파일 존재 확인은 Glob으로 함(`ls` 대신)

- **`subagent_type`은 `.claude/agents/{에이전트명}.md`의 에이전트명을 씀**(`AGENTS.md` 팀원 위임 규칙).

  절이 산출물별 세부 인격을 더함. **실행 환경의 사용 가능 에이전트 목록에 그 이름이 없으면**(이 스킬만
  다른 프로젝트에 배포된 경우) `subagent_type="general-purpose"`로 대체 호출하며, 이때 인격은 프롬프트
  파일만으로 실림. 대체 호출한 사실은 5단계 완료 보고 표의 호출 방식 열에 `general-purpose 대체`로 적음.
  서브에이전트 기능이 없는 도구(예: Antigravity)에서 실행되면 오케스트레이터가 그 프롬프트의 `[역할]`을

- **담당 배정 근거**: 배정을 이 스킬이 새로 판정하지 않음. `prompts/README.md` 2절 파일 목록의

  사용자에게 보고함

  MCP 도구를 쓰지 않음([맥락] 도구 제약). 따라서 머리말이 지정한 스택니(`stackni`)에게 위임하고,

- **순서8이 커넥니가 아닌 옵스니인 이유**: 이미지ㆍ매니페스트ㆍ상태 확인ㆍ되돌리기는 연결ㆍ인증과 다른

- **모달니ㆍ에듀니를 배정하지 않는 이유**: 개발 프롬프트 9종 중 STTㆍTTSㆍVLM을 다루는 항목과 코드 해설

  여부를 물음. 만든 코드의 해설 페이지가 필요하면 `explain-exam` 스킬(에듀니)을 별도로 실행함
- **협업 패턴 판정**: 전체 뼈대는 **파이프라인형**에, 서로 의존이 없는 하위 단계(순서2ㆍ3ㆍ4,

  동시 진행임

### 1단계 — 입력 수집

- 스킬 실행 시작과 동시에 AskUserQuestion **1회** 호출로 [입력] 1ㆍ2ㆍ4행 5개 항목(기획산출물
  경로, 설계서 경로, 프론트엔드 스택, 코드 루트 경로, 상태저장 백엔드)을 함께 입력받음(왕복을
  줄이기 위해 분리 호출하지 않음)
- 기획 산출물 Base 디렉토리는 존재 여부와 하위 파일 개수(1개 이상)를 Glob으로 확인함
- 값이 없거나 경로가 비어 있으면 AskUserQuestion으로 동일 항목을 재질문함(**재질문 카운터 최대
  2회**). 2회째도 값이 없으면: 기본값이 있는 항목([입력] 2행)은 기본값으로 진행하고, 기본값이 없는
  항목([입력] 1ㆍ4행)은 사용자 응답이 올 때까지 다음 단계로 진행하지 않음(경로ㆍ선택값을 임의로
  추정해 진행하지 않음). 사용자가 "기본값으로 진행"이라 하면 즉시 기본값을 씀
- [입력] 3행의 고정값 4종은 사용자에게 묻지 않고 그대로 적용함

### 2단계 — `개발환경정보.md` 인스턴스 생성 (한 번만)

  표 열 구성ㆍ1절의 값의 주인 표뿐임. 아래 "예시 기본값을 이어받음"은 **제품ㆍ도구 종류를 고르는
  칸에 한정**하며(패키지 매니저ㆍ시험 도구ㆍ주입 방식ㆍ이름 규격), 프로젝트 고유값

  - 재질문 카운터ㆍ재작성 카운터 2회 초과 시 값을 임의로 추정해 진행하지 않음
  - 비밀값(API 키ㆍ토큰ㆍ비밀번호 등) 실제 값을 서브에이전트 프롬프트나 산출물에 그대로 옮기지 않음
  - `git add`ㆍ`git commit`ㆍ`git push` 등 되돌리기 어려운 git 작업은 사용자가 이 스킬 실행 중

**순서2ㆍ3ㆍ4 병렬 위임 호출 형태(Claude Code `Agent` 도구 기준 — 다른 도구는 같은 담당·병렬 규칙을 그 도구의 서브에이전트 기능으로 옮김)** (하나의 메시지 안에서 3건 동시 호출)
```
Agent(subagent_type="jisikni", description="02-dataset.md 실행",
      prompt="{작업용 복사본}/02-dataset.md 파일을 Read로 전체를 읽고, 머리말 `> 담당 인격:`과
              [역할] 절의 인격을 그대로 취한 뒤 요약ㆍ축약 없이 수행하라",
      run_in_background=true)
Agent(subagent_type="connectni", description="04-connector.md 실행",
      prompt="{작업용 복사본}/04-connector.md 파일을 Read로 전체를 읽고 (같은 형식으로) 수행하라",
      run_in_background=true)
Agent(subagent_type="connectni", description="05-guardrail.md 실행",
      prompt="{작업용 복사본}/05-guardrail.md 파일을 Read로 전체를 읽고 (같은 형식으로) 수행하라",
      run_in_background=true)
```
`subagent_type`이 팀원 정의(`.claude/agents/`)를 싣고, 각 파일의 머리말ㆍ`[역할]` 절이 산출물별 세부
인격을 더함. 에이전트명이 사용 가능 목록에 없으면 세 호출 모두 `general-purpose`로 바꾸고 나머지는 동일함.
