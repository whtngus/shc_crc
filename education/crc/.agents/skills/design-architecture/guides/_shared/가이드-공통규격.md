# 설계 가이드 공통 규격

`prompts/`의 설계 산출물 7종 작성 프롬프트를 **사람이 읽고 스스로 설계할 수 있는 가이드**로
옮기기 위한 규격임. 가이드 7건은 `guides/` 아래에 두며 이 규격을 공유함.

---

## 전문 용어 규칙

**독자는 아키텍트·개발자·검토자임.** 업계 표준 전문 용어를 **그대로** 씀:
쉬운 말로 옮기면 뜻이 좁아지고, 구현 단계에서 찾아볼 원어와 이어지지 않음.

- **G1** **전문 용어는 업계 표기 그대로 씀**: `RRF` · `HNSW` · `Prompt Injection` ·
  `Kill-Switch` · `Circuit Breaker` · `Grounding`. 우리말로 새로 옮기거나 의역하지 않음
- **G2** **약어는 처음 나올 때만 원어를 괄호로 병기함**: `RRF(Reciprocal Rank Fusion)`.
  이후에는 약어만 씀. 쉬운 말로 풀어 쓴 문장을 덧붙이지 않고 별도 용어표도 두지 않음
- **G3** 이 체계의 규격 부호(`HARD`·`CYCLE`·`T-1`·`C-A1` 등)는 **정의한 자리에서 한 번만** 정의하고
  이후에는 부호만 씀
- **G4** "적절히"·"충분히"·"잘" 금지. 판단 기준은 숫자나 예/아니오 질문으로 씀
- **G5** 지시가 아니라 **설명**으로 씀. `~하시오`가 아니라 `~함` / `~이 낫습니다`
- **G6** 표를 우선함. 3개 이상 나열은 표로 바꿈
- **G7** 한 줄 120자 제약은 **산문과 목록에만 적용함.** 표 행은 줄바꿈이 안 되므로 제외함.
  실제 작성에서 4명이 같은 지적을 했음(④③⑥⑦)
- **G8** **규칙을 먼저 쓰고 근거는 한 번만 붙임.** 근거를 앞에 길게 깔면 규칙이 묻힘
- **G9** **규칙이 사실임을 증명하는 문장을 넣지 않음.** 조사는 가이드를 쓸 때 하는 일이고
  읽는 사람은 규칙을 지키려고 읽음. **표가 이미 보인 것을 문장으로 다시 쓰지 않음**
- **G10** **굵은 항목명·소제목은 규칙을 말함.** 무엇에 관한 이야기인지만 알리는 제목을 두지 않음
  (`고유키는 무엇이 막나임` ✗ → `값이 빠질 수 있으면 IS NODE KEY를 고름` ✓)

## 산출물 1건은 무엇으로 이뤄지나

| 무엇 | 어디서 오나 |
|------|------------|
| **본문 절 구성** | **그 가이드 3절의 제목 구조를 그대로 씀**: 여기 없는 절을 만들지 않고, 있는 절을 빼지도 않음 |
| **본문 항목** | 3절의 **굵은 항목명** 목록. 순서도 그대로 |
| **말미 부속 표** | 아래 4종에서 그 설계서에 해당하는 것(0건이어도 `0건`으로 적음) |

문서 1건 = 마크다운 파일 1개. 파일명은 프롬프트 규격과 같게 씀.

7종이 다 끝나면 **`00-반영대조표.md` 1건을 더 만듦**: 대응 프롬프트가 없어 사람이 직접 씀.

## 부속 표 4종의 열 구성

7종이 똑같이 씀. 열을 늘리거나 이름을 바꾸지 않음.

| 부속 표 | 열 구성 |
|---------|--------|
| 제외 지표 | 지표 / 분류(공동 책임·책임 밖) / 탈락 테스트 번호 / 목표값 / 근거 출처 |
| 미대응 Pain Point | 기획서의 Pain Point / 이번 범위에서 안 다루는 이유 / 언제 다루나 |
| 대조 기록 | 기획 항목 ID / 반영 여부(반영·부분반영·범위외·미반영) / 반영 위치 / 사유 |
| 미확정 항목 | `[확인필요]` 태그 / 무엇이 없나 / 누구에게 되묻나 / 안 오면 무엇이 막히나 |

**`변경요청` 표**는 앞 산출물로 값을 되돌리는 자리임: `무엇 / 받는 곳 / 사유` 3열.
0건이어도 표를 만듦.

## 근거 출처 표기법: 본문 표의 마지막 열

형식은 `{약칭}:{항목 ID}#{하위}`임. **약칭은 아래 5개만 씀. 새로 만들지 않음.**

| 약칭 | 무엇의 줄임말 | 예 |
|------|--------------|-----|
| BM | 비즈니스 모델: 린 캔버스·핵심 지표가 적힌 기획 문서 | `BM:8-KeyMetrics#고객가치1` |
| US | 유저스토리: 기능(UFR)·비기능(NFR) 요구가 적힌 문서 | `US:NFR-SYS-020#마스킹` |
| ES | 이벤트스토밍: 업무 흐름 도식 파일 | `ES:02#참여자` |
| PR | 프로젝트 개요: 과제 정의서·제안 자료 | `PR:3#To-Be흐름` |
| 설계판단 | 원문 근거가 없고 팀이 정한 것 | `설계판단` |

`UFR`은 기능 요구, `NFR`은 비기능 요구, `AFR`은 공통·부가 요구임.

- **규제·안전 점검 항목의 근거도 이 5개에서 찾음**: 탐색 순서는
  `US NFR 컴플라이언스 → ES 규제 반영표 → 없으면 [확인필요]`임
- 원문에 값이 없으면 지어내지 않고 `[확인필요: 무엇]`으로 남기고 미확정 항목 표에 1행 적음
- **`근거 출처` 열은 본문 표에만 둠**: 부속 표 4종은 위 열 구성을 그대로 쓰고 이 열을 두지 않음
- **예외: ④ 역할계약서**는 이 열을 두지 않음: 표B를 단계 1개 = 행 1개로 쪼개면서 칸 수가
  늘어난 만큼 간결성을 우선해 출처 추적을 빼기로 함(설계판단, 트레이드오프로 받아들임).
  값의 출처가 궁금하면 그 단계의 원문(US·③ 워크플로우)을 직접 대조함. 다른 6종은
  이 절의 규칙을 그대로 씀
- **선행 설계서를 인용할 때** 새 약칭을 만들지 않고 **그 값의 원문 ID**를 씀.
  원문에 없는 판단이면 `설계판단`에 괄호로 출처를 병기함(예: `설계판단`(② 논리아키텍처 TB-2 통과 항목 표))

## 값의 주인: 어느 문서가 무엇을 소유하나

**같은 값이 두 문서에 있으면 한쪽만 고쳐질 때 어느 쪽이 진짜인지 모르게 됨.**
아래 표의 주인만 그 값을 정하고, 나머지는 **인용**하거나 아예 적지 않음.

| 값 | 주인 | 다른 문서는 |
|----|------|-----------|
| 우선 품질속성 · 목표값 · 성격 선언(고영향·고위험) | ① 목표/품질 카드 | ③이 성격 선언을 인용 |
| 민감정보 라벨 목록 · 경계 식별자(`SL-n`) · Mock·실물 구분 | ② 논리아키텍처 | ⑤가 인용 |
| 단계ID · **State 필드 이름** · **프로세스별 API 설계의 엔드포인트·요청/응답 키 이름** | ③ 워크플로우 | ④는 엔드포인트 이름을 인용만, 키를 펼쳐 적지 않음 |
| **타임아웃 · 재시도 · 반복 상한(`max_iter`)** | ③ 워크플로우 | **⑥은 옮겨 적지 않음**: 볼 일이 있으면 ③ 표를 봄 |
| **단계 패턴 · 정보 검색 워크플로우 패턴**(4문 Q1~Q4 조합. 문헌 이름 Self-RAG·Adaptive RAG·CRAG·Agentic RAG는 참고 라벨) | ③ 워크플로우 2-2 | ⑤는 그 판정 단계가 쓸 **임계값·보낼 경로**만 채움(패턴을 정하면 ③→④→⑤가 순환함) |
| **체크포인트 보존 사유 · 스레드 식별 단위 · 세션 격리 키 성분 · 스레드 최소 생존 시간** | ③ 워크플로우 | ⑦이 존재 여부를 읽어 물리 배치도에 이름만 얹음. 개발은 키의 **문자열 조립 문법**만 정함 |
| 체크포인트 **보관 기간 · 파기 방식** · 적재 금지 필드 · 저장 암호화 요건 | ⑤ 지식/도구 3-3 | ③의 `스레드 최소 생존 시간`을 하한으로 받아 확정 |
| 체크포인터 **저장 등급 · 안/밖 배치 · 접속정보 · 백업 대상** | **설계 범위 밖** | 구현·운영 단계에서 결정함. ⑦은 존재 여부만 물리 배치도에 표시 |
| **모델 호출 횟수(`0회`·`N회`)** | ③ 워크플로우 | ④가 읽어 담당자 종류를 가름(다시 판정하지 않음) |
| 담당자 수·묶음 · 저장소의 **논리 이름**(표A) · 도구의 **논리 이름과 권한 등급**(표B) · 승인자 짝짓기 · 사용 모델 | ④ 역할계약서 | ⑥이 표B의 도구 권한 등급을 읽어 승인 지점을 뽑음 |
| **조회 대상** 테이블·열 · 커넥터 ID · 커넥터 요청·응답 키 · 민감 필드 ID(`F-n`) · 변환 지점 · **저장소 제품과 색인 파라미터** | ⑤ 지식/도구 | ⑥이 `F-n`과 **가리는 방법을 인용**해 기록 계열에 거는 곳을 정함. **④에는 키·민감 필드가 없음**. 접속정보는 설계 범위 밖 |
| 비용 금액·상한·초과 처리 · 기록 항목 · 출력측 검사 방식 · **마스킹을 거는 곳(기록 계열)** · 차단 규칙 · **입력측 불신 표시 방법 · 호출·동시성·위임 깊이 상한 · 연속 실패 차단 기준** | ⑥ 관측/가드레일 | ⑦이 적재처 이름을 인용해 물리 배치도에 얹음. **가리는 방법 자체는 ⑤ 소유라 인용만 함**. 적재처 제품·전송 키는 설계 범위 밖 |
| 구성요소의 **물리 배치**(실행환경 단위 그림 1개) | ⑦ 배포 | ②의 구성요소를 그대로 인용. 포트·비밀값 주입 경로·저장소 세부 배치는 **설계 범위 밖** |
| 골든셋 문항 · 원천 오류율 · 통과율 | **설계서가 아님: 별도 품질 튜닝** | 설계 단계에는 접속 정보·실데이터가 없어 실측이 성립하지 않음 |

**뒤 문서로 옮길 수 있는 값은, 앞 문서가 그 값 없이도 문서를 닫을 수 있는 값뿐임.**
비용은 ③이 안 쓰므로(횟수까지만 소유) ⑥이 가짐. 타임아웃은 ③이 최악값·예산 대조에 쓰므로 ③ 것임.

**어긋나는 것이 나오면 그 자리에서 고치지 않고 `변경요청` 1행만 앞으로 되돌려 보냄.**
