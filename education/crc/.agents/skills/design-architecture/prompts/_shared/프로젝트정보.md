# 프로젝트 정보 기입란 — 설계 프롬프트 7종 공용 입력

> 설계 프롬프트 7종(`prompts/01-*.md` ~ `07-*.md`)이 **공통으로 읽는 단 하나의 입력 파일**임.  
> 프롬프트를 실행하기 **전에** 이 파일을 먼저 채움. 여기가 비면 뒤 산출물이 시작 지점에서 막힘.

**이번 기입 대상 프로젝트** — 런치픽(LunchPick). 기획 산출물은 `~/workspace/lunch-aws-actions/docs/plan/`임.  
기입: 클로니(총괄) · 원문 확인: 지식니(`V-04`·`V-07` 2·3행) · 커넥니(`V-06`·`V-10`·`V-07` 4·6행) ·
모달니(`V-05`·지연 전제) · 기입일 2026-08-08

## 1. 쓰는 법

- 이 파일을 복사하지 않고 **여기에 직접 값을 적음**. 프롬프트가 이 경로를 그대로 읽음
- 값을 모르면 빈칸으로 두지 않고 `프로젝트 확정 필요`라고 적음
- 값을 적을 때는 **근거 출처를 같은 행에 함께 적음**. 출처 표기 형식은
  `guides/_shared/가이드-공통규격.md`의 「근거 출처 표기법」을 따름
- 팀이 정한 값이면 출처 칸에 `설계판단`이라고 적음

**차단 규칙** — 어떤 프롬프트를 실행할 때 그 산출물이 쓰는 변수가 `프로젝트 확정 필요`로
남아 있으면 프롬프트는 **작성을 시작하지 않고 사용자에게 문의함.** 비운 채 진행하지 않음.

**적힌 값을 그대로 믿지 않음** — 실제 테스트에서 잘못 적힌 값 때문에 없는 데이터 위에 설계가
선 사례와, `0건`으로 적힌 점검 항목이 실은 해당했던 사례가 있었음.  
그래서 `V-04`(데이터 원천)·`V-10`(규제·안전 점검)은 **적힌 값을 그대로 쓰지 않고
기획 산출물 원문에서 다시 확인한 뒤** 씀. `0건`으로 적힌 점검 항목도 다시 판정함.

**이번 기입에서 실제로 다시 확인한 결과 2건** — 위 두 사례가 이번에도 그대로 재현됨.

| 재확인 항목 | 결과 |
|------------|------|
| `V-04`의 `원재료·알레르겐 표시` | **오분류 확인.** 원문 5곳 전수 확인 결과 전부 **사용자 입력 쪽**임. 식당·메뉴가 어떤 재료를 쓰는지 알려 주는 원천은 기획 원문에 **없음**. 유일한 후보였던 `음식 성분 DB 교차 검증`(A35)은 탈락 확정임 |
| `V-10`의 `자동 확정 금지`·`출력 측 노출 검사` | **둘 다 0건 아님.** 자동 확정 금지 8건(결제·해지·발송·배치 커밋 등), 출력 측 노출 검사 6건(LLM 추천 이유·학습 반영 메시지·인사이트 요약·푸시 본문 등)임 |
