# 파이썬 주석 작성 가이드

## 0. 적용 범위
- 적용 대상: 팀에서 작성하는 모든 파이썬 코드(앱·서비스·에이전트·테스트·실행 스크립트)
- 함께 보는 문서: `references/layered-architecture-guide.md` (계층별 주석 포인트는 §6에서 연결)
- 참고 표준: [PEP 8 Comments](https://peps.python.org/pep-0008/#comments),
  [PEP 257 Docstring Conventions](https://peps.python.org/pep-0257/)
- 규칙 충돌 시 우선순위: 본 가이드 > PEP 8·PEP 257

## 1. 한 줄 원칙
**코드는 "무엇을 하는지"를, 주석은 "왜 그렇게 하는지"를 말함**

- 코드만 읽어도 알 수 있는 내용은 주석으로 반복하지 않음
- 코드만 읽어서는 알 수 없는 내용(이유·제약·전제·외부 기술의 특이 동작·보안 의도)을 주석으로 남김
- 주석은 코드와 한 몸임. 코드를 고치면 주석도 같은 커밋에서 함께 고침

## 2. 주석 종류와 위치
| 종류 | 위치 | 쓰는 내용 | 필수 여부 |
|------|------|-----------|-----------|
| 모듈 docstring | 파일 맨 첫 줄 | 이 파일이 맡는 역할 한 줄 | 필수 |
| 클래스 docstring | `class` 바로 아래 | 책임, 주입받는 것, 하지 않는 것 | 공개 클래스 필수 |
| 함수 docstring | `def` 바로 아래 | 한 줄 요약 + 목적·방법·반환값·예외 | 공개 함수·포트 메서드 필수 |
| 블록 주석 | 코드 묶음 위 | 여러 줄에 걸친 처리의 목적과 방법 | 필요 시 |
| 줄 끝 주석 | 코드 오른쪽 | 단위, 허용 범위, 짧은 이유 | 필요 시 |

- 공개(public): 이름이 `_`로 시작하지 않는 모듈·클래스·함수
- 비공개(`_` 시작) 함수도 동작이 한눈에 보이지 않으면 한 줄 docstring을 붙임

## 3. 문체 규칙
- 언어: 한국어. 코드 식별자·라이브러리 이름·고유 용어는 원문 그대로 씀(예: `QueryPlan`, RLS, RRF)
- 종결: 명사체 사용(팀 마크다운 가이드와 동일)  
  "조회합니다" → "조회함", "반환한다" → "반환함", "~이다" → "~임"
- 쉬운 말: 처음 나오는 약어·전문 용어는 한 번 풀어 씀  
  예: `# RRF(여러 검색 결과의 순위를 합치는 방식) 점수 = 가중치 / (상수 + 순위)`
- 길이: 주석·docstring 한 줄은 120자 이내. 넘으면 줄을 나눔
- 기호: `#` 뒤에 공백 1칸. 줄 끝 주석은 코드와 공백 2칸 이상 띄움(PEP 8)
- 전각 공백(`　`)·전각 기호를 쓰지 않음. 오탈자는 코드 리뷰에서 수정 대상임

## 4. docstring 표준 형식

### 4.1 한 줄 docstring
동작이 단순하면 한 줄로 끝냄
```python
def month_end(value: date) -> date:
    """주어진 날짜가 속한 달의 마지막 날짜를 반환함."""
```

### 4.2 여러 줄 docstring
한 줄 요약 → 빈 줄 → 항목 순서로 씀. 해당 없는 항목은 생략함
```python
def retrieve_customer_snapshot(self, member_id: str, base_date: date) -> dict:
    """고객 현황 전체 묶음을 조회함.

    목적: 한 회원의 프로필·카드·최근 이용실적·연체 현황을 근거와 함께 제공함.
    방법: 읽기 전용 트랜잭션에서 회원과 기준일 범위를 설정한 뒤 논리 뷰를 각각 조회함.
    인자: base_date는 데이터 기준일 이하만 허용함.
    반환값: 조회 데이터, 출처, 기준일, 경고를 담은 dict임.
    예외: 기준일이 범위를 벗어나면 SearchError("invalid_base_date")를 발생시킴.
    """
```

| 항목 | 쓰는 내용 | 쓰지 않는 내용 |
|------|-----------|----------------|
| 목적 | 이 함수가 있어야 하는 이유(업무 관점) | 함수 이름을 풀어 쓴 문장 |
| 방법 | 핵심 처리 순서 1 ~ 2문장 | 코드 한 줄씩 옮긴 설명 |
| 인자 | 타입 힌트로 드러나지 않는 의미·단위·허용 범위 | 인자 이름과 타입의 반복 |
| 반환값 | 무엇이 담기는지, 빈 값·None의 의미 | 반환 타입 이름만 적기 |
| 예외 | 호출자가 처리해야 하는 예외와 발생 조건 | 내부에서 잡아서 처리하는 예외 |
| 예시 | 경계 사례가 이해를 돕는 경우의 입출력 예 | 뻔한 정상 사례 |

- 타입은 타입 힌트로 표현함. docstring에 타입을 다시 적지 않음
- 부수효과(파일 쓰기, 외부 호출, 캐시 변경)가 있으면 `방법:` 또는 별도 `부수효과:` 항목에 반드시 적음

### 4.3 클래스 docstring
책임 한 줄 + 주입받는 것 + 하지 않는 것을 적음
```python
class RetrieverService:
    """검색·답변·스트림·헬스체크 기능을 제공함.

    실제 실행은 생성자로 주입받은 그래프 실행 포트(RetrieverGraphPort)에 맡김.
    구현체 생성은 하지 않으며, 조립은 app/bootstrap.py가 담당함.
    """
```

### 4.4 설정·데이터 필드
필드 오른쪽 줄 끝 주석으로 의미와 단위를 적음
```python
@dataclass(frozen=True)
class ServiceLimits:
    """API 표현 계층이 쓰는 호출 예산·제한 시간 값. 설정에서 읽어 bootstrap이 주입함."""

    max_llm_calls_per_request: int = 2  # API 요청 한 건의 LLM 호출 상한
    request_timeout_seconds: float = 120.0  # Retriever 요청 전체의 제한 시간(초)
```
- pydantic 모델은 `Field(description=...)`에 설명을 넣음. OpenAPI 문서에도 그대로 노출됨

## 5. 블록 주석과 줄 끝 주석

### 5.1 반드시 주석을 다는 경우
| 경우 | 예시 |
|------|------|
| 직관과 다른 처리 | `# 회원 조건을 SQL에 넣지 않음. RLS(행 단위 접근 제어)가 세션 범위의 한 회원만 보여 줌.` |
| 외부 라이브러리의 특이 동작 | `# 빈 dict를 넘기면 psycopg가 SQL 안의 %를 자리표시자로 해석함. None을 그대로 전달함.` |
| 보안·개인정보 의도 | `# 파싱 대상 SQL과 DB 식별자는 오류 메시지에 포함하지 않음.` |
| 순서가 중요한 처리 | `# 회원 범위를 먼저 열어야 RLS가 아래 회원 조회에 행을 내어 줌.` |
| 매직 넘버·상수 | `k=60  # RRF 논문 권장 상수. 순위 차이를 완만하게 만듦` |
| 일부러 하지 않는 처리 | `# 행 수는 세지 않음. 범위를 열기 전에 센 값은 언제나 0이라 뜻이 없음.` |

### 5.2 목적·방법 블록 형식
여러 줄에 걸친 처리는 `목적:` · `방법:` · `예시:` 머리말로 구조화함
```python
# 목적: 복합 질문의 일부 하위 질문 결과가 RRF 순위 경쟁에서 모두 밀려나는 것을 방지함.
# 방법: 각 하위 질문의 상위 per_query_top_k개를 먼저 배치하고, 나머지 RRF 결과를 기존 순서로 이어 붙임.
# 예시: original → A 1위, B 2위 / transformed_1 → B 1위, C 2위
```

## 6. 계층별 주석 포인트
`references/layered-architecture-guide.md`의 계층 구조 기준

| 계층 | 주석에 꼭 남길 것 |
|------|-------------------|
| domain | 업무 규칙의 근거(정책·규정·요구사항 ID), 경계값의 의미 |
| application/models.py | 필드 제약의 이유, 오류 코드의 의미와 HTTP 상태 |
| application/ports.py | **계약 전체**: 입력 전제, 반환값 의미, 발생 가능한 예외, 부수효과 여부 |
| application/services | 처리 흐름 순서와 분기 기준(예: 언제 LLM을 부르지 않는지) |
| infrastructure | 외부 기술의 특이 동작, 타임아웃·재시도 값의 근거, 보안 설정 이유 |
| presentation | 서비스 오류 → 응답 코드 변환 규칙 |
| bootstrap.py | 구현체 선택 기준(어떤 설정값일 때 무엇을 고르는지) |
| tests | 테스트가 보증하는 규칙. 함수 이름으로 드러나지 않으면 한 줄 docstring |

포트 docstring 예시 (형식 설명용. 반환 키·예외는 실제 코드와 다를 수 있음)
```python
class RepositoryPort(Protocol):
    """요청 회원의 정형 데이터를 읽기 전용으로 조회하는 계약."""

    @abstractmethod
    def search(self, member_id: str, base_date: date, validated_sql: str) -> dict:
        """검증된 논리 SQL을 회원·기준일 범위 안에서 실행함.

        인자: validated_sql은 SQL 검사기를 통과한 문장만 전달함.
        반환값: rows·sources·warnings 키를 가진 dict임. 결과가 없으면 rows가 빈 리스트임.
        예외: 범위를 벗어난 조회는 SearchError를 발생시킴.
        부수효과: 없음(읽기 전용).
        """
```

## 7. 표시 태그
| 태그 | 뜻 | 형식 |
|------|----|------|
| `TODO` | 나중에 할 일 | `# TODO(닉네임, YYYY-MM-DD): 할 일 — 완료 조건` |
| `FIXME` | 알려진 결함 | `# FIXME(닉네임, YYYY-MM-DD): 증상 — 재현 조건` |
| `HACK` | 임시 우회 | `# HACK(닉네임, YYYY-MM-DD): 우회 이유 — 제거 조건` |

- 날짜는 절대 날짜로 적음("다음 주" 같은 상대 표현 금지)
- 완료 조건·제거 조건이 없는 태그는 리뷰에서 반려함

## 8. 금지 사항
| 금지 | 나쁜 예 | 고친 예 |
|------|---------|---------|
| 코드 그대로 반복 | `# reranking 점수로 정렬` | 주석 삭제 (코드가 이미 말함) |
| 행 번호 참조 | `# 자료형 검사(51 ~ 63라인)가 자동 수행` | `# 필드 선언의 자료형 검사가 먼저 자동 수행됨` |
| 호출 경로 추적 | `# graph.py의 _run_reranker의 score가 호출됨` | `# RerankerPort.score로 점수를 받음` (포트 기준으로 씀) |
| 주석 처리된 코드 | `# result = old_search(query, k=5)` | 삭제. 이력은 Git이 보관함 |
| 비밀값·실제 개인정보 | `# 테스트 키: gsk_...`, 실제 회원ID·전화번호 | 가짜 값(`M-0001`)만 사용 |
| 오래된 주석 | 코드와 다른 동작을 설명하는 주석 | 코드 수정 시 같은 커밋에서 갱신 |
| 교재 강조 표기 | `# ◀ 포트만` | 교재·슬라이드 발췌에만 사용, 실제 소스에는 쓰지 않음 |

- 행 번호·다른 파일의 내부 함수명은 코드가 바뀌면 바로 틀려지므로 쓰지 않음
- DIP 구조에서는 구현체 이름 대신 **포트 이름**으로 설명함. 구현체가 바뀌어도 주석이 유효함

## 9. 교육용 예제 코드 예외
- 학습자가 읽는 예제(`hybrid-ai-lab/` 등)는 줄 단위 설명 주석을 허용함
- 단, §8 금지 사항(행 번호·호출 경로·주석 처리된 코드)은 예제에서도 그대로 적용함
- 설명이 길어지면 주석 대신 해설 문서(eduni·`explain-exam` 스킬)로 분리함

## 10. 점검 체크리스트
완료 보고 전 아래 항목을 확인함
- [ ] 모든 모듈 첫 줄에 역할 한 줄 docstring이 있음
- [ ] 공개 클래스·공개 함수·포트 메서드에 docstring이 있음
- [ ] 포트 docstring에 입력 전제·반환값·예외·부수효과가 적혀 있음
- [ ] 종결이 명사체("~함", "~임")로 통일되어 있음
- [ ] 코드를 반복하는 주석, 행 번호 참조, 주석 처리된 코드가 없음
- [ ] 비밀값·실제 개인정보가 주석에 없음
- [ ] 수정한 코드의 주석이 현재 동작과 일치함

### 10.1 자동 점검 명령 (선택)
docstring 누락 검사(ruff의 pydocstyle 규칙)
```bash
ruff check --select D100,D101,D102,D103 app
```
행 번호 참조·주석 처리된 import 찾기 (결과는 사람이 한 번 더 보고 판단함. 설명용 인용일 수 있음)
```bash
grep -rnE "#.*[0-9]+ ?(~|-) ?[0-9]+ ?(라인|줄|행)|^\s*# ?(from|import) " app
```
