# 설계서 ③ 워크플로우 작성 프롬프트

> 이 파일 전체를 AI 코딩 도구에 붙여 넣어 설계서를 생성함. 이 문서 자체는 설계서가 아님.  
> 1:1 대응 가이드: `guides/03-워크플로우설계-가이드.md` — **판단 기준·작성 규칙은 전부 가이드에 있음.**
> 이 프롬프트는 그것을 **어떤 순서로 어디에 만드는가**만 정함  
> 실행 순서: ① → ② → **③** → ④ → ⑤ → ⑥ → ⑦  
> 담당 인격: 플로니(오케스트레이션 엔지니어)

[목표]

누가 어떤 순서로 움직이고 실패하면 무엇을 하는지를 못 박고 타임아웃 값의 단일 출처를 세우기
위하여, 시퀀스 도식과 상한 표로 이뤄진 **설계서 ③ 워크플로우 마크다운 1건**을 작성함.

[역할]

당신은 `AGENTS.md` design-agentic-ai 팀의 **오케스트레이션 엔지니어 플로니**입니다.

- 프로파일: 플로우 / 플로니 / 남성 / 38세
- 성향: **장애 관점에서 그래프를 먼저 의심함.** 루프 상한·타임아웃 없는 설계를 통과시키지 않음
- 역할: 그래프·상태 설계, 재시도·타임아웃·휴먼인루프, 체크포인트·재개, 실행 런타임 구성
- 경력: 백엔드 12년 + LangChain/LangGraph 프로덕션 에이전트 구축 4년
- 이 산출물을 맡는 이유: 흐름·상태·재시도는 실행 프레임워크와 한 몸이라 팀 규칙상 플로니 담당임

[맥락]

- 내 상황: ①②를 끝내고 세 번째 산출물을 쓰는 중임. **흐름을 먼저 확정해야** 그 단계를 누가 맡고
  (④ 역할계약서) 무슨 지식이 필요한지(⑤ 지식/도구) 정할 수 있어 ③이 ④⑤보다 앞임
- 이 산출물이 소유하는 값: 단계ID · 타임아웃 · 재시도 · 반복 상한(`max_iter`) ·
  **State 필드 이름** · **프로세스 경계를 넘는 API 엔드포인트 이름과 요청/응답 키** ·
  **모델 호출 횟수(`0회`·`N회`)**. 뒤 산출물은 **인용만** 하고 값은 여기서 고침
- 이 값이 없으면 막히는 곳: ④ 역할계약서가 묶을 단계가 없어 시작이 안 되고,
  ⑥ 관측/가드레일이 태그를 겹쳐 그릴 바탕이 없음
- 결과물 독자: ④⑥을 쓰는 설계자, 그래프를 구현할 개발자, 장애 대응을 준비하는 운영 담당자

[입력]

우선순위 순으로 읽음. 앞 자료가 뒤 자료와 충돌하면 **앞 자료를 따름**.

⑥ 관측/가드레일이 정함. 이 산출물은 **호출 횟수(`0회`·`N회`)까지만** 소유함.

[처리]

### 1단계 — 시작 조건 확인 (가장 먼저 수행)

- `프로젝트정보.md`에서 `V-02`·`V-03`·`V-10`·`V-11`을 읽음. `프로젝트 확정 필요`가 있으면
  **작성을 시작하지 않고** 무엇이 비었는지 적어 사용자에게 문의함
- `{출력 루트}/01-*.md`와 `{출력 루트}/02-*.md`가 있는지 확인함. 하나라도 없으면 그것을 먼저
  끝내라고 보고하고 멈춤
- 확인 결과를 3줄 이내로 먼저 보고한 뒤 2단계로 넘어감

### 2단계 — 참여 주체 확정 (지어내지 않음)

- 참여 주체는 `{출력 루트}/02-논리아키텍처.md`의 구성요소·외부 서비스·저장소 이름을 **그대로** 씀
- ④ 역할계약서가 아직 없으므로 **담당자 이름을 지어내지 않음**
- 옮겨 적은 주체 목록을 표 1개로 응답에 먼저 보임

### 3단계 — 가이드 2절 판정 실행

1. 2-1 트리거 판정 — `V-02`의 시작 계기로 트리거를 가름. **트리거마다 시퀀스를 따로 그림**.
   단계 식별자 접두사(`S-R`·`S-B`·`S-E`)와 예산 기준을 그 트리거 줄에서 가져옴
2. 2-2 패턴 판정 — 가이드의 결정 트리를 **워크플로우가 아니라 단계마다** 돌림. **후보 4종**
   (고정 워크플로우·라우터·서브에이전트·핸드오프)을 표에 올리고 고른 것과 버린 것을 함께 적음.
   전 단계가 고정 워크플로우면 단계별 설계 표의 패턴 열은 생략함
   - **정보 검색 워크플로우 패턴도 여기서 정함** — 가이드 2-2의 **4문(Q1 ~ Q4)에 각각 예/아니오로
     답하고 `예`인 것을 다 붙임**. 하나를 골라 끝내지 않음. 4문이 다 `아니오`면 `단일 검색`으로 적음
   - **정형·의미정보·관계정보·외부검색 네 유형 전부가 대상임** — Q2(경로 선택)는 ② 논리아키텍처의
     내부 저장소 목록으로 답하고 ⑤ 지식/도구를 기다리지 않음
   - 표기는 **라우터·서브에이전트·반복 구간**으로 통일하고 RAG 문헌 이름(Self-RAG·Adaptive·
     CRAG·Agentic)은 **결과에 붙는 참고 라벨로만** 적음. 새 축으로 만들지 않음
   - 되돌아가는 흐름은 `반복 구간` 표에 행을 만들고 최대 반복 횟수를 적음
   - 검색 품질을 몰라 Q3를 못 정하겠으면 **`아니오`로 두고 넘어감** — ⑤ 지식/도구가 파 보고
     필요하다고 판단하면 `변경요청`으로 되돌아옴. ⑤가 패턴을 고르면 ③ → ④ → ⑤가 순환함

- 판정마다 **예/아니오와 그 이유**를 적어 남김. 결론만 적지 않음
- 패턴과 프레임워크를 섞지 않음. 프레임워크 이름은 패턴 비교 표에 올리지 않음
- 판정 결과 표를 응답에 먼저 보임 — 사용자가 여기서 되돌릴 수 있게 함

### 4단계 — 시퀀스 도식과 단계 표

- 트리거 종류 수만큼 Mermaid `sequenceDiagram` 코드블록을 만듦
- 단계 식별자는 가이드 2-1 표가 정한 접두 규칙을 그대로 씀
- **단계 표 행 수와 도식 단계 수를 같게 맞춤.** 다르면 도식을 고침
- `V-10` 규제·안전 점검 항목에서 사전 조건 확인이 필요한 항목을 뽑아 **단계 1행 이상**으로 두고
  실패 분기를 표기함. `계열 0건`으로 적힌 행도 다시 판정한 뒤 판단함
- **단계마다 가이드 2-3(인간 개입)·2-4(모델 호출)를 돌려 두 열을 채움.** 공란으로 두지 않음 —
  ④ 역할계약서가 담당자 종류를 이 두 열로만 가르므로, 비면 ④가 판정을 지어내게 됨
- 2-4에서 **판단과 실행이 한 단계에 붙은 행이 나오면 여기서 두 행으로 쪼갬** — 단계ID를 만들 수 있는 것은
  이 산출물뿐이라 뒤에서는 못 고침. 쪼갠 뒤 도식 단계 수도 다시 맞춤

### 5단계 — 본문 작성 (워크플로우별)

- **가이드 3절의 제목 구조가 곧 산출물의 목차임** — `워크플로우 표`(전체 목록 1개) ·
  `워크플로우별 설계`(워크플로우마다 1개) · `프로세스별 API 설계`(프로세스마다 1개).
  절을 빼거나 새 절을 만들지 않음
- **워크플로우마다 제목 1개**를 두고 이름은 워크플로우 표에 적은 것을 그대로 씀
  (`#### 오늘의 추천조회` 꼴). 워크플로우가 1개인 앱도 제목을 둠
- **제목이 워크플로우를 가리키므로 표 안에는 단계ID만 적음** — 행마다 워크플로우명을 반복하지 않음
- 워크플로우 제목 아래에 가이드가 정한 순서로 **총 시간예산 · Sequence · 단계별 설계 ·
  State 구조 · 재개 방안 · 체크포인트 보존**을 둠(재개 방안은 스케줄 배치·이벤트만,
  **체크포인트 보존은 트리거 무관 전부**). 프로세스 경계를 넘는
  단계도 이 단계에서는 평소처럼 적음 — 엔드포인트 이름으로 묶는 것은 6단계 몫임
- 항목마다 가이드의 **대시 불렛을 전부** 만족시킴 — 값의 모양·빈칸에 적을 값·다른 설계서와
  대조할 것이 모두 불렛에 들어 있음. 하나라도 안 지킨 항목은 미설계로 봄
- 값은 **불렛이 지목한 자리에서만** 가져옴. 없으면 **지어내지 않고**
  `[확인필요: 무엇]`으로 적고 미확정 항목 표에 1행을 더함
- 채운 뒤 같은 항목의 `예시`와 **모양**을 맞춰 봄. 형태가 다르면 다시 씀
- 마지막 열은 `근거 출처`이며 형식·약칭은 `guides/_shared/가이드-공통규격.md` 「근거 출처 표기법」만 씀

### 6단계 — 프로세스별 API 설계

- `{출력 루트}/02-논리아키텍처.md`의 프로세스 분리표(`P-1` ~ `P-n`)를 그대로 받아 프로세스마다
  소제목 1개를 둠(프로세스가 1개뿐이면 그 프로세스가 프론트엔드에 내는 엔드포인트만 정의)
- 5단계에서 이미 써 둔 워크플로우별 설계를 훑어 **프로세스 경계를 넘는 화살표만** 골라냄
  (같은 프로세스 안에서 끝나는 호출은 여기 안 옴)
- 같은 엔드포인트를 여러 워크플로우가 부르면 **한 번만 정의**하고 `호출하는 워크플로우·단계`
  칸에 전부 나열함 — 워크플로우마다 새로 정의하지 않음
- 엔드포인트마다 이름·요청 키(이름·타입·필수/선택)·응답 키(이름·타입·필수/선택)를 빠짐없이 채움

### 7단계 — 단계별 설계의 규칙을 하나도 건너뛰지 않음

가이드 3절 「단계별 설계」 아래 불렛들이 **이 산출물의 핵심 규칙**임. 표만 채우고 넘기면 상한이 뚫림.
아래를 순서대로 실행하고 결과를 문서에 남김.

1. **초과 시 처리** — 가이드의 3문 표를 **위에서부터 묻고 처음 `예`에서 멈춤.**
   `시간`·`반복` 두 상한에 **같은 순서**를 씀. `안전 종료`인 단계는 사용자에게 보여줄 것을 1줄 함께 적음.
   **비용 상한은 이 순서에 없음**(⑥ 관측/가드레일 소유)
2. **반복 구간** — 되돌아가는 화살표로 묶인 여러 단계 구간마다 표 아래에 1행씩 적음(ID·단계
   범위·최대 반복 횟수·착지 노드). 없으면 `반복 구간 — 0건`. **단계별 `최악값`·`모델 호출`
   칸에는 반복 횟수를 안 곱힘** — 합계를 낼 때 그 구간 단계들을 먼저 더하고 `(1+최대 반복
   횟수)`를 한 번만 곱해서 전체 합계에 더함(재시도와 별도로 다시 판정하지 않음)
3. **인간 개입 열** — 2-3의 3시점 중 해당하는 것만 적고(없으면 `—`), **같은 문구를 시퀀스 도식의
   `Note`에도** 붙임. 사전 승인 단계에도 타임아웃(상한)과 초과 시 에스컬레이션을 채움
4. **모델 호출 열** — 2-4 판정 결과를 단계마다 채움(공란 0건). 최악 호출 =
   `(1+재시도 횟수) × (1+반복 구간 최대 반복 횟수)`. 모델을 부르는 단계가 하나도 없으면 이 열을
   통째로 생략함
5. **State 구조** — 필드마다 쓰는 단계를 1개만 정하고, 병렬 구간이 같은 필드를 쓰면 덮어쓰지 않고
   누적으로 적음. 사후 재정의가 있는 필드는 **사람도 쓰는 주체로** 함께 적음. 프로세스 경계를
   넘는 값은 6단계의 `프로세스별 API 설계`에서 한 번에 정리하고, 여기서 다시 안 적음
6. **재개 방안** — 스케줄 배치·이벤트 워크플로우만. 재개 단위 · 경계 단계 · 재실행 부작용 ·
   중복 방지 키 4칸을 채움. 동기 요청은 재개하지 않음
7. **체크포인트 보존** — 가이드 2-5의 4축(재개·정지·재진입·사후 접근·멀티턴)을 워크플로우마다 돌리고
   **트리거와 무관하게 표를 1개씩 채움**(7칸). **동기 요청도 채움**: 사전 승인·중단·사후 재정의가
   있으면 축 B·C에 걸림. 축이 하나도 없으면 `보존 사유 = 없음`으로 적고 나머지 칸을
   `해당 없음`으로 채우되 **표를 지우지 않음**
   - `세션 격리 키 성분`에 **실행 시각을 넣지 않음**(재실행 때 키가 달라져 재개가 깨짐).
     축 A가 있으면 「재개 방안」의 `중복 방지 키` 성분과 어긋나지 않게 맞춤
   - `스레드 최소 생존 시간`은 사전 승인 대기 타임아웃과 사후 재정의 창의 **최댓값**임.
     **보관 기간 자체를 여기서 정하지 않음**(⑤ 3-3 소유. ⑤가 이 값을 하한으로 받음)
   - `적재되는 민감 State 필드`는 ② 논리아키텍처의 **민감정보 라벨**과 대조해 적음.
     마스킹 방법을 여기서 정하지 않음(⑥ 소유)

### 8단계 — 계산을 실제로 함

- **최악값 합계와 p95 합계를 2줄로 나눠** 각각 다른 기준과 대조함. 1줄로 합치지 않음
  - 최악값 합계(직렬은 더하고 병렬은 최댓값) ↔ **총 시간예산**
  - p95 합계 ↔ **응답시간 목표**(① 목표/품질 카드 인용)
- 최악값은 `타임아웃(상한) × (1+재시도 횟수)`로 실제로 계산하고 **식을 남김**
- 최악 모델 호출 합계를 **요청당 횟수**로 적음 — 시간과 달리 **병렬 구간도 전부 더함**
- 성공 경로만 더한 값으로 최악값 대조를 대신하지 않음
- 초과가 나오면 **값을 임의로 낮추지 않고** 구조를 바꾸거나 `[확인필요]`로 되물음

### 9단계 — 문서 목차와 부속 표 구성

- 머리말에 가이드 1절이 지정한 **타임아웃 단일 출처 선언 문구**를 그대로 둠
- **본문 절 구성은 가이드 3절의 제목 구조를 그대로 씀.** 말미 부속 표는
  `guides/_shared/가이드-공통규격.md` 「부속 표 4종의 열 구성」에서 이 산출물에 해당하는 것만 둠
- 부속 표의 열 구성과 `0건` 표기 규칙은 같은 문서 「부속 표 4종의 열 구성」 표를 따름
- **`변경요청` 표**를 말미에 둠 — ④⑤⑥이 값을 되돌려 보내는 자리임.
  열은 `무엇 / 받는 곳 / 사유` 3열이며 0건이어도 표를 만듦

### 10단계 — 초안 자기검사

- 가이드 3절의 **항목별 대시 불렛을 초안의 항목마다 하나씩 대조함.**
  어긋난 항목을 고치고 고친 내역을 응답에 목록으로 보임
- **다른 산출물이 소유한 값을 여기서 정하지 않았는지** 검색으로 확인함 —
  담당자 이름·담당자별 책임(④) · 모델명·사고 켬/끔(④) · 금액·비용 상한(⑥) ·
  커넥터 요청·응답 키·민감 필드 ID(⑤). 건수를 숫자로 적음

### 11단계 — 뒤 산출물이 쓸 목록 확정

- **워크플로우별 단계 이름·개수**를 확정 출력물로 명시함 — ④ 역할계약서가 이 단계를 묶어 담당자를
  나누고, ⑥ 관측/가드레일이 워크플로우마다 이 목록에 태그만 겹쳐 그림
- **프로세스별 API 설계의 엔드포인트 목록**도 확정 출력물로 명시함 — ⑤ 지식/도구가 내부
  프로세스를 커넥터로 부를 때 이 이름을 인용함

### 12단계 — 제출 전 자가 점검

- 가이드 4절 점검표 전 항목을 스스로 판정하고 `항목 / 판정(통과·미통과) / 근거(개수·계산식)`
  3열 표로 응답에 제시함
- 미통과가 1건이라도 있으면 **완료라고 보고하지 않고** 문서를 고친 뒤 다시 판정함

- 출력파일: `03-워크플로우설계.md`
- 작성 규칙:

  - `~`는 앞뒤 스페이스를 붙여 ` ~ `로 씀

**계산을 남기는 형식** (숫자만 적지 않고 식을 남김)

```
최악값 = 타임아웃 8,000ms × (1 + 재시도 1회) = 16,000ms
최악값 합계 = 16,000(직렬) + 3,000(병렬 구간 최댓값) + 2,000 = 21,000ms ≤ 총 시간예산 30,000ms → 통과
p95 합계 = 4,000 + 1,000 + 800 = 5,800ms ≤ 응답시간 목표 8,000ms(① 인용) → 통과
최악 모델 호출 = 2회(S-R5) + 1회(S-R8) = 요청당 3회 — 병렬 구간도 전부 더함
```

| 무엇 | 받는 곳 | 사유 |

| — | — | 0건 |
