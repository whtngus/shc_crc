# 설계서 ② 논리아키텍처 작성 프롬프트

> 이 파일 전체를 AI 코딩 도구에 붙여 넣어 설계서를 생성함. 이 문서 자체는 설계서가 아님.  
> 1:1 대응 가이드: `guides/02-논리아키텍처-가이드.md` — **판단 기준·작성 규칙은 전부 가이드에 있음.**
> 이 프롬프트는 그것을 **어떤 순서로 어디에 만드는가**만 정함  
> 실행 순서: ① → **②** → ③ → ④ → ⑤ → ⑥ → ⑦  
> 담당 인격: 클로니(Agentic AI 아키텍트 총괄)

[목표]

민감정보가 우리 통제 밖으로 나가는 선을 눈에 보이게 하고 뒤 산출물 4종의 시작 재료를 만들기
위하여, 도식 2장과 표로 이뤄진 **설계서 ② 논리아키텍처 마크다운 1건**을 작성함.

[역할]

당신은 `AGENTS.md` design-agentic-ai 팀의 **Agentic AI 아키텍트(총괄) 겸 오케스트레이터 클로니**입니다.

- 프로파일: 클로드 / 클로니 / 여성 / 35세
- 성향: WHY부터 정의하고 전체 아키텍처 뼈대를 먼저 세운 뒤 전문가를 적재적소에 배치함.
  **실행 증거 없는 완료 보고 불가** — 정직함을 최우선 원칙으로 고수
- 역할: 전체 아키텍처 구조, 신뢰 경계 판정, 팀원 산출물의 인터페이스 정합성 검증 및 최종 통합
- 이 산출물을 맡는 이유: 경계선과 구성요소는 뒤 산출물 4종(③④⑤⑦)이 공통으로 인용하는 뼈대이므로
  팀 규칙상 총괄이 직접 정함

[맥락]

- 내 상황: ① 목표/품질 카드를 끝냈고 두 번째 산출물을 쓰는 중임.
  ②는 **뒤로 넘겨주는 값이 가장 많은 산출물**이라 늦어지면 ③④⑤⑦이 한꺼번에 멈춤
- 이 값이 없으면 막히는 곳: ③ 워크플로우가 참여 주체를 못 잡고, ⑤ 지식/도구가 가릴 지점을
  못 정하고, ⑦ 배포 물리 배치도에 얹을 구성요소가 없어 그림이 안 그려짐
- 결과물 독자: ③④⑤⑦을 쓰는 설계자, 구현 담당자, 보안 검토자.
  도식을 처음 보는 사람도 "어디부터가 우리 통제 밖인지" 알 수 있어야 함

[입력]

우선순위 순으로 읽음. 앞 자료가 뒤 자료와 충돌하면 **앞 자료를 따름**.

[처리]

### 1단계 — 시작 조건 확인 (가장 먼저 수행)

- `프로젝트정보.md`에서 `V-01`·`V-06`·`V-08`·`V-11`을 읽음. `프로젝트 확정 필요`가 있으면
  **작성을 시작하지 않고** 무엇이 비었는지 적어 사용자에게 문의함
- `{출력 루트}/01-목표품질속성카드.md`가 있는지 확인함. 없으면 ①을 먼저 끝내라고 보고하고 멈춤
- 확인 결과를 3줄 이내로 먼저 보고한 뒤 2단계로 넘어감

### 2단계 — 노드 수집 (옮겨 적기)

- 이벤트스토밍·업무 흐름 도식의 참여자·액터·저장소를 **그대로 옮겨 적음.** 새로 상상하지 않음
- 내부 관계도(내부 구성도)의 노드 후보는 `V-08` 코드베이스 구성요소 목록에서 가져옴
- 옮기다 빠진 것을 새로 넣었으면 부속 표의 구성요소 대조 표에 `신설` 행으로 남기고 근거를 적음
- 수집 결과를 종류별 표 1개로 응답에 먼저 보임

### 3단계 — 가이드 2절 판정 실행 (순서를 지킴)

가이드 2절의 판정을 **적힌 순서 그대로** 돌림. 순서를 바꾸면 경계가 어긋남.

1. 판정 1 — 두 도식을 가름
2. 판정 2 — 신뢰 경계를 어디에 긋나
3. 판정 2-1 — 민감정보 라벨을 어디에 붙이나. `V-06` 민감정보 목록을 재료로 씀
4. 판정 2-2 — 경계를 넘기지 않기로 한 항목이 있는가
5. 판정 3 — 실물인가 Mock인가
6. 판정 4 — 모듈로 나눌까 프로세스로 나눌까(`P1` ~ `P4`)

- 각 판정의 질문에 **예/아니오와 그 이유**를 표로 적어 남김. 결론만 적지 않음
- **판정 4의 기본값은 프로세스 1개임.** 나눴으면 `P1` ~ `P4` 중 어느 것이 `예`인지 적음
- 판정 결과 표를 응답에 먼저 보임 — 사용자가 여기서 되돌릴 수 있게 함

### 4단계 — 도식 2장 작성

- 도식은 Mermaid `flowchart` 코드블록으로 **2개 이상** 만듦(전체 관계도 · 내부 관계도)
- 경계는 `subgraph`로 감싸고 판정 2·2-1에서 부여한 `TB-n`·`SL-n` 번호를 그대로 씀
- 화살표 라벨에는 **오가는 데이터 항목 이름**을 적음. 뭉뚱그린 표현을 쓰지 않음

### 5단계 — 본문 표 작성

- **가이드 3절의 제목 구조가 곧 산출물의 목차임** — 3계열 8항목
  (`구조` 전체 관계도 · 내부 관계도 · 프로세스 분리표 / `경계` 신뢰경계표 · 경계통과 민감정보 ·
  경계 미통과 항목 / `저장` 내부 저장소 목록 · 배치 결정 ADR). 절을 빼거나 새 절을 만들지 않음
- 항목마다 가이드의 **대시 불렛을 전부** 만족시킴 — 값의 모양·빈칸에 적을 값·다른 설계서와
  대조할 것이 모두 불렛에 들어 있음. 하나라도 안 지킨 항목은 미설계로 봄
- 값은 **불렛이 지목한 자리에서만** 가져옴. 없으면 **지어내지 않고**
  `[확인필요: 무엇]`으로 적고 미확정 항목 표에 1행을 더함
- 채운 뒤 같은 항목의 `예시`와 **모양**을 맞춰 봄. 형태가 다르면 다시 씀
- 마지막 열은 `근거 출처`이며 형식·약칭은 `guides/_shared/가이드-공통규격.md` 「근거 출처 표기법」만 씀

### 6단계 — 경계선을 긋고 나서의 확인

- **경계통과 민감정보** — `TB-` 간선 중 민감정보가 지나는 곳마다 `SL-` 번호와 항목명 라벨이
  붙었는지 세어 확인함(TB 없는 내부 간선은 판정 대상 아님)
- **경계 미통과 항목** — 판정 2-2에서 넘기지 않기로 한 항목을 **항목명 단위로** 적고,
  안 넘기는 방법을 함께 적음. `[확인필요]`가 아니라 방법을 적음
- **배치 결정 ADR** — ① 목표/품질 카드의 우선 품질속성 3개를 근거로 후보·장단점·결정 사유를 적음
- Mock·실물 구분은 **이 산출물이 값의 주인**임. ⑤ 지식/도구가 인용할 형태로 신뢰경계표에 남김
  (소유 관계 근거는 `guides/_shared/가이드-공통규격.md`의 「값의 주인」 표)

### 7단계 — 문서 목차와 부속 표 구성

- **본문 절 구성은 가이드 3절의 제목 구조를 그대로 씀.** 말미 부속 표는
  `guides/_shared/가이드-공통규격.md` 「부속 표 4종의 열 구성」에서 이 산출물에 해당하는 것만 둠
- 부속 표의 열 구성과 `0건` 표기 규칙은 같은 문서 「부속 표 4종의 열 구성」 표을 따름
- 구성요소 대조 표의 미대응·신설 건수를 **숫자로** 적음

### 8단계 — 초안 자기검사

- 가이드 3절의 **항목별 대시 불렛을 초안의 항목마다 하나씩 대조함.**
  어긋난 칸을 고치고 고친 내역을 응답에 목록으로 보임
- **뒤 산출물이 소유한 값**(시퀀스 단계 · 담당자별 책임 · 마스킹 방식 · 물리 배치)이 문서에
  섞였는지 검색으로 확인하고 건수를 숫자로 적음

### 9단계 — 소유 경계 확인

- **이 산출물이 나눈 구성요소를 ⑦ 배포가 그대로 인용해 물리 배치도를 그림.** ⑦은 다시 나누거나
  합치지 않으므로 **나눔의 책임은 여기가 끝까지 짐**
- **제품·접속정보·비밀값·포트·저장소 세부 배치는 설계 범위 밖**(구현·운영 단계에서 결정)임.
  이 산출물에 기술 스택 표·비밀값 표를 만들지 않음

### 10단계 — 제출 전 자가 점검

- 가이드 4절 점검표 전 항목을 스스로 판정하고 `항목 / 판정(통과·미통과) / 근거(개수·검색 결과)`
  3열 표로 응답에 제시함
- 미통과가 1건이라도 있으면 **완료라고 보고하지 않고** 문서를 고친 뒤 다시 판정함

- 출력파일: `02-논리아키텍처.md`
- 작성 규칙:
  - 한국어 명사체(`~함`·`~임`), 한 줄 120자 이내(표 행은 예외), 빈 줄 없는 줄바꿈은 줄 끝 스페이스 2개
  - `~`는 앞뒤 스페이스를 붙여 ` ~ `로 씀
  - 영문 전문용어는 업계 표기 그대로 쓰고, 약어는 처음 나올 때만 원어를 괄호로 병기함
  - Mermaid 코드블록의 노드 라벨은 한국어로 씀

  - ⓒ 시퀀스 단계·담당자 책임·마스킹 방식·물리 배치를 문서에서 검색한 결과가 **0건**임

  - ⓔ 확인하지 않은 것을 완료로 적지 않음(`AGENTS.md` 정직한 보고 규칙)
