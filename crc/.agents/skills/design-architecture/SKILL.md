[목표]
기획 산출물(비즈니스모델·유저스토리·이벤트스토밍)의 값을 아키텍처 설계로 옮기기 위하여,
사용자가 지정한 기획 산출물 디렉토리를 입력으로 아키텍처 설계서 7종
(목표/품질 카드 → 논리아키텍처 → 워크플로우 → 역할계약서 → 지식/도구 → 관측/가드레일 → 배포)과
반영대조표 1종을 정해진 순서로 생성하는 유저스코프 스킬 실행

[역할]
design-agentic-ai 팀의 오케스트레이터 클로니가 산출물별 담당자에게 실제 위임하여 진행함.
담당자 전환은 문서상 서술로 끝내지 않고 `Agent` 도구로 서브에이전트를 실제 호출함(패턴은 문서상
선언이 아니라 실제 Agent 호출로 실행함 · 정직한 보고 규칙). **담당 인격은 두 겹으로 실림** —
`subagent_type`에 `.claude/agents/`의 에이전트명(`flonie`·`jisikni`·`connectni`·`opsni`)을 지정해
팀원 정의를 싣고, 프롬프트 7종 각각의 `[역할]` 절(프로파일·성향·경력·"이 산출물을 맡는 이유")을
`prompt` 인자로 넘겨 산출물별 세부 인격을 더함. 에이전트명이 실행 환경에 없으면 `general-purpose`로
대체 호출하되 인격은 `[역할]` 절이 실어 옴. 담당 배정표·판정 근거·협업 패턴 분류는 [처리] 0단계에 둠.

[맥락]
- 내 상황: `prompts/` 프롬프트 7종과 `guides/` 가이드 7종을 매번 손으로 복사해 AI 코딩 도구에
  붙여 넣던 방식을 스킬로 패키징해 재사용하고 싶음. 종전 방식은 인격만 바꿔 한 명이 전부 썼으나,
  이번 개선으로 산출물마다 별도 서브에이전트를 실제로 띄워 위임하도록 바꿈
- 결과물 독자: 이 스킬을 실행하는 프로젝트의 아키텍트·개발자. 산출물은 뒤 단계(개발·배포) 담당자가
  그대로 읽고 구현 근거로 삼음
- 비용 특성: 가이드 7종은 각 단계 자가 점검에만 쓰이는 절이 있어, 전문을 매 단계 반복해 읽으면
  같은 내용을 여러 번 컨텍스트에 태우는 낭비가 생김 — [처리]에서 발췌 읽기로 제한함
- 서브에이전트는 매 호출마다 컨텍스트가 새로 시작되므로, 호출 시 해당 단계 프롬프트 파일 전문 +
  가이드 「제출 전 자가 점검표」 절 발췌 + 직전 단계 산출물 중 참조가 필요한 절만 전달하고,
  대화 이력 전체나 그 앞 절들의 전문은 `prompt` 인자에 담지 않음(비용 최소화). 점검표 앞의
  절들은 프롬프트 [입력] 순위 2가 지목한 경로를 서브에이전트가 직접 Read하므로 이중 적재가
  생기지 않음
- 도구 제약: 이 스킬은 Bash·PowerShell을 쓰지 않음. 프롬프트 완료조건이 "실제 `ls` 결과를 첨부"로
  적은 자리는 **Glob 조회 결과**로 대신하며, 서브에이전트에도 같은 방식을 지시함

  (비즈니스모델·유저스토리·이벤트스토밍 산출물 파일이 있는 디렉토리)
- 아키텍처 설계서 Base 디렉토리: 스킬 실행 시작 직후 같은 AskUserQuestion 호출로 함께 입력받는
  절대경로(미존재 시 신규 생성 대상, 이 디렉토리 하위에 설계 산출물 8건 저장)
- 프로젝트 정보 입력 양식: `{스킬 디렉토리}/prompts/_shared/프로젝트정보.md`(1절 쓰는 법 ·

[처리]

### 0단계 — 담당 배정 확인 (실행 파일을 만들지 않는 판정 단계)
- `{스킬 디렉토리}/prompts/README.md` 2절 표에서 산출물별 담당 인격을 그대로 가져옴(재해석하지
  않음). 결과는 아래와 같음

| 산출물 | 담당 인격(프롬프트 `[역할]` 값) | 호출 방식 |
|---|---|---|
| ① 목표/품질 카드 | 클로니 — 아키텍트 총괄 | 클로니 직접(Agent 호출 없음) |
| ② 논리아키텍처 | 클로니 — 아키텍트 총괄 | 클로니 직접(Agent 호출 없음) |
| ③ 워크플로우 | 플로니 — 오케스트레이션 엔지니어 | Agent 호출 1회(`subagent_type="flonie"`) |
| ④ 역할계약서 | 플로니 — 오케스트레이션 엔지니어 | Agent 호출 1회(`subagent_type="flonie"`) |
| ⑤ 지식/도구 | 지식니 — 지식·데이터 엔지니어 | Agent 호출 1회(`subagent_type="jisikni"`) |
| ⑥ 관측/가드레일 | 커넥니 — 도구 연동 엔지니어 | Agent 호출 1회(`subagent_type="connectni"`) |
| ⑦ 배포 | 옵스니 — 플랫폼·배포 엔지니어 | Agent 호출 1회(`subagent_type="opsni"`) |
| `00-반영대조표.md` | 클로니 — 최종 통합 | 클로니 직접(대응 프롬프트 없음) |

- **`subagent_type`은 `.claude/agents/{에이전트명}.md`의 에이전트명을 씀**(`AGENTS.md` 팀원 위임 규칙).
  위 표의 값을 그대로 지정하고, 프롬프트 파일 `[역할]` 절이 산출물별 세부 인격을 더함.
  **실행 환경의 사용 가능 에이전트 목록에 그 이름이 없으면**(이 스킬만 다른 프로젝트에 배포된 경우)
  `subagent_type="general-purpose"`로 대체 호출하며, 이때 인격은 `[역할]` 절만으로 실림.
  대체 호출한 사실은 6단계 완료 보고 표의 호출 방식 열에 `general-purpose 대체`로 적음.
  서브에이전트 기능이 없는 도구(예: Antigravity)에서 실행되면 오케스트레이터가 그 프롬프트의 `[역할]`을
  취해 순차로 직접 수행하고, 완료 보고의 호출 방식 열에 `직접 수행(서브에이전트 없음)`으로 적음
- ①②는 프롬프트 `[역할]`이 클로니 본인이므로 오케스트레이터가 직접 수행함.
  `00-반영대조표.md`는 대응 프롬프트가 없는 최종 통합 성격이라 역시 직접 수행함
- 협업 패턴 판정: 전체 뼈대는 **파이프라인형**(각 프롬프트 `[입력]`의 "선행 산출물" 행 —
  ③~⑦은 `(필수)` 표시로 시작 불가 조건까지 못 박음 — 이 순서 고정·출력=입력 의존을 실증함).
  **되돌림 구간 없음** — ④는 논리 이름과 등급까지만 정하고 구체화는 ⑤가 끝내므로 ④를 되짚을 값이
  없음(prompts/README 3절 "④ ⇄ ⑤ 왕복은 없음"이 같은 내용을 선언함).
  어긋나는 것이 나오면 그 자리에서 고치지 않고 `변경요청` 1행만 앞으로 되돌려 보냄
- 모달니(STT·TTS·VLM·요약)·스택니(API·화면 구현)·에듀니(코드 해설)는 이 스킬 범위에 해당 산출물이
  없어 호출 대상 아님(정상). 설계서 7종은 구현·해설이 아니라 설계 문서임

### 1단계 — 입력 수집
- 스킬 실행 시작과 동시에 AskUserQuestion **1회** 호출로 기획 산출물 Base 디렉토리, 아키텍처 설계서
  Base 디렉토리 2건을 함께 입력받음(왕복을 줄이기 위해 분리 호출하지 않음)
- 기획 산출물 Base 디렉토리는 존재 여부와 하위 파일 개수(1개 이상)를 Glob으로 확인함
- 존재하지 않거나 하위 파일이 0개이면 AskUserQuestion으로 동일 항목을 재질문함(**재질문 카운터
  최대 2회**). 2회째도 미해결이면 실행을 중단하고 사유를 사용자에게 보고함(경로를 임의로 추정해
  진행하지 않음)
- 아키텍처 설계서 Base 디렉토리는 존재하지 않으면 신규 생성 대상으로 간주하고 재질문 없이 진행함

### 2단계 — 프로젝트 정보 채움 (한 번만)
- `{스킬 디렉토리}/prompts/_shared/프로젝트정보.md`의 변수 12종(V-01 ~ V-12) **구조와 표 열 구성만**
  그대로 가져와 `{설계서 Base 디렉토리}/_shared/프로젝트정보.md`를 새로 만듦
- **양식 3절 기입란에 채워진 값은 다른 프로젝트(런치픽) 견본이므로 한 칸도 이어받지 않음** —
  기입 대상 프로젝트명·기입자·기입일 머리말, V-01 ~ V-12의 모든 값 행, 「재확인 항목」 2행,
  「미확정 항목」 12행을 전부 비우고 이 프로젝트의 값으로 다시 채움. 견본 값이 하나라도 남아
  있으면 미작성으로 봄
- 값은 기획 산출물 Base 디렉토리의 원문에서만 채움. 원문에 근거가 없는 변수는 값 칸에
  `프로젝트 확정 필요`라고 적음(공란 금지 — 12종 전부 값 또는 `프로젝트 확정 필요`로 채움)
- 값을 채운 변수는 같은 행의 `근거 출처` 칸에 출처를 병기함. 형식·약칭은 스킬이 새로 정하지 않고
  `guides/_shared/가이드-공통규격.md` 「근거 출처 표기법」의 `{약칭}:{항목 ID}#{하위}`를 그대로 씀
  (약칭은 `BM`·`US`·`ES`·`PR`·`설계판단` 5개만. 예: `US:NFR-SYS-020#마스킹`).
  팀이 정한 값은 `설계판단`으로 적음
- 원문에 개인정보(실명·연락처·주민등록번호 등), 계정·시크릿·API 키·인증정보가 포함돼 있으면 원문
  그대로 옮기지 않고 마스킹 처리(예: 실명→가상 이름, 이메일·전화번호→형식만 남긴 예시, 키·비밀번호
  →`[마스킹됨]`)한 뒤 기록하고, 원문 위치(파일명·절)만 출처로 남김
- `V-11`(기획 산출물 경로)엔 1단계에서 입력받은 기획 산출물 Base 디렉토리 경로를, `V-12`(출력 루트
  경로)엔 1단계에서 입력받은 아키텍처 설계서 Base 디렉토리 경로를 그대로 적음
- `V-04`(데이터 원천)와 `V-10`(규제·안전 점검 항목)은 **적힌 값을 그대로 믿지 않고** 항목을 하나씩
  기획 산출물 원문과 대조하여 O/X 임시 체크리스트를 만든 뒤, X 항목은 `프로젝트 확정 필요`로 확정함 —
  `0건`으로 적힌 점검 항목도 다시 판정함
  (`prompts/_shared/프로젝트정보.md` 1절 「적힌 값을 그대로 믿지 않음」이 같은 규칙을 담음)
- 이 단계 종료 시점에 `프로젝트 확정 필요`가 남아 있고 그 변수를 이후 단계(③ ~ ⑦)가 실제 사용할
  예정이면, 다음 단계로 넘어가지 않고 즉시 AskUserQuestion으로 사용자에게 값 확정을 요청함

### 3단계 — 설계서 7종 순차 생성 (실행 순서: ① → ② → ③ → ④ → ⑤ → ⑥ → ⑦)

**①②(클로니 직접 작성)**
- `{스킬 디렉토리}/prompts/0N-*.md`(N=1,2)를 읽어 지시대로 직접 작성하고
  `{설계서 Base 디렉토리}/0N-*.md`에 저장함. 프롬프트 [입력] 순위 2가 지목한 가이드
  `{스킬 디렉토리}/guides/0N-*.md`의 2절 판정·3절 설계항목은 직접 읽어 적용함(상대경로를
  스킬 디렉토리 기준으로 해석하므로 별도 치환이 필요 없음)
- 작성 직후 그 프롬프트의 [처리] 마지막 단계(「제출 전 자가 점검」)를 스스로 실행함(①②는 가이드 4절). 미통과 항목이 있으면 스스로
  고쳐 다시 점검하되 **재작성 카운터 최대 2회**까지만 반복함. 2회째도 미통과면
  `[확인필요: 미통과 사유]`를 표기하고 다음 산출물로 진행함(③~⑦과 동일 규칙)

**③~⑦(서브에이전트 실제 위임)**
- 인격만 바꿔 클로니가 대신 쓰지 않고 반드시 아래처럼 `Agent` 도구로 **실제 호출**함
  1. `{스킬 디렉토리}/prompts/0N-*.md` 프롬프트 파일 전체를 읽어 **경로 치환 3종**을 적용함.
     치환 없이 넘기면 서브에이전트가 상대경로를 찾지 못해 [입력] 순위 2·3의 "실행 불가. 중단하고
     보고"로 떨어짐

     | 원문 문자열 | 치환값 |
     |---|---|
     | `prompts/_shared/프로젝트정보.md` | 2단계에서 만든 파일의 절대경로 |
     | `guides/...`(가이드 7종 · `guides/_shared/가이드-공통규격.md`) | `{스킬 디렉토리}/guides/...` 절대경로 |
     | `{출력 루트}` · `output/design/` | `{아키텍처 설계서 Base 디렉토리}` 절대경로 |

  2. 자가 점검에 필요한 **「제출 전 자가 점검표」 절**만 Grep으로 찾음(절 번호는 ③~⑥이 4절,
     **⑦은 3절** — [입력]의 절 구성 표 참조. 번호로 찾지 않고 **제목 문자열로** 찾음).
     가이드 `01~07-*.md` 전문은 오케스트레이터가 읽지 않음 — 나머지 절은 프롬프트 [입력] 순위 2에
     따라 서브에이전트가 치환된 절대경로로 직접 읽음
  3. 서로 다른 출처의 텍스트를 하나의 `prompt` 인자에 담을 때는 반드시 XML 태그로 구분함 —
     `<프롬프트지시>{치환된 프롬프트 전문}</프롬프트지시>`,
     `<가이드점검표>{발췌한 「제출 전 자가 점검표」 절}</가이드점검표>`,
     `<선행산출물>{직전 단계 산출물 중 참조가 필요한 절}</선행산출물>`
  4. `Agent(subagent_type="{0단계 표의 에이전트명}", description="설계서 0N-* 작성",
     prompt=<위 3종 태그를 이어붙인 문자열>, run_in_background=false)`로 호출함
     (③④ `flonie` · ⑤ `jisikni` · ⑥ `connectni` · ⑦ `opsni`). 에이전트명이 사용 가능 목록에
     없으면 `general-purpose`로 대체하고 그 사실을 기록함. 산출물별 세부 인격은 `<프롬프트지시>` 안의
     `[역할]` 절이 실어 옴(0단계 표 참조)
  5. 앞 산출물이 다음 산출물의 필수 입력이므로(각 프롬프트 `[입력]`의 "선행 산출물(필수)" 행 참조)
     **순차(foreground) 호출만 하며 병렬 호출하지 않음**
  6. 호출 완료 후 Glob으로 산출물 파일이 실제 생성됐는지 확인한 뒤에만 다음 번호로 넘어감. 파일명은
     임의로 정하지 않고 해당 프롬프트의 [출력] 섹션에 명시된 값을 그대로 사용함(예: 04번은
     `04-에이전트역할계약서.md`, 07번은 `07-배포설계.md`)
  7. 프롬프트 [처리] 마지막 단계(「제출 전 자가 점검」)에서 미통과 항목이 있으면 같은 방식으로
     재호출해 고치되 **재작성 카운터 최대 2회**까지만 반복함. 재호출 시 `prompt`에는
     `<프롬프트지시>{치환된 프롬프트 전문}</프롬프트지시>`,
     `<직전산출물>{직전 호출이 만든 산출물 전체}</직전산출물>`,
     `<미통과항목>{점검표 미통과 항목 목록}</미통과항목>` 3종을 함께 전달함. 2회째도 미통과 항목이
     남으면 `[확인필요: 미통과 사유]`를 표기하고 다음 단계로 진행함(무한 재작성 금지)

### 4단계 — 되돌아가는 자리 1곳 반영
- ③ 완료 직후: 클로니가 직접 ①번 산출물 파일 **말미**의 `③ 분해 결과 회신` 칸(①번 프롬프트

  결과를 옮겨 적음(1회만 갱신, ①은 클로니 소유값이라 Agent 재호출 불필요). 해당 칸이 없으면
  `[확인필요: 회신 칸 없음]`으로 남기고 다음 단계로 진행함

  (`prompts/README.md` 3절 "④ ⇄ ⑤ 왕복은 없음"이 같은 내용을 선언함).
  ⑤가 ④에 없는 저장소·도구가 필요하다고 판단하면 ④를 고치지 않고 ⑤ 산출물의
  `변경요청` 표에 1행을 남기며, 그 행은 사용자에게 보고만 하고 자동 반영하지 않음

  - 경로 미존재로 인한 재질문(재질문 카운터)은 최대 2회까지만 수행함
  - ③~⑦ 산출물은 반드시 `Agent(subagent_type="{0단계 표의 에이전트명}", ...)` 실제 호출로
    작성하며, 오케스트레이터가 인격만 바꿔 직접 쓰지 않음. 에이전트명이 없는 환경에서만
    `general-purpose`로 대체하고, 산출물별 세부 인격은 `prompt`에 담은 프롬프트 `[역할]` 절이 실어 옴
  - Agent에 넘길 프롬프트 전문에 3단계 경로 치환 3종(프로젝트정보.md · `guides/...` ·
    `{출력 루트}`·`output/design/`)을 모두 적용함
  - ③~⑦의 Agent 호출은 순차(foreground)로 진행하며, 앞 호출의 산출물 파일이 실제 생성된 것을
    확인한 뒤에만 다음 호출의 입력으로 사용함
  - ①~⑦ 산출물 전부, 자체·재호출 자가점검(재작성 카운터)에서 미통과 시 최대 2회까지 고친 뒤에만
    `[확인필요]` 표기로 넘어가며 완료로 보고함
  - 값이 없으면 `[확인필요: 무엇]` 또는 `프로젝트 확정 필요`로 남기고 지어내지 않음
  - 프로젝트정보.md의 `프로젝트 확정 필요`가 후속 단계에 필요한 채 남아 있으면 즉시
    AskUserQuestion으로 확정받은 후에만 다음 단계로 진행함
  - 기획 산출물 원문의 개인정보·계정·시크릿·인증정보는 마스킹 후에만 설계서·프로젝트정보.md에 기록함
  - 서로 다른 출처(프롬프트 지시문·가이드 발췌·선행 산출물)를 하나의 Agent `prompt` 인자에 담을 때는
    반드시 XML 태그로 구분함
  - 완료 보고 전 민감정보 최종 스캔을 수행함
- MUST NOT:
  - 프로젝트정보.md에 `프로젝트 확정 필요` 항목이 남아 있는 변수를 사용하는 산출물의 작성을 시작하지
    않음
  - `prompts/_shared/프로젝트정보.md` 3절 기입란의 견본 프로젝트(런치픽) 값을 새 프로젝트의
    프로젝트정보.md·설계서에 옮기지 않음
  - 사용 가능 에이전트 목록에 없는 `subagent_type`을 지정하지 않음 — 0단계 표의 에이전트명이 목록에
    없으면 호출 실패를 기다리지 않고 `general-purpose`로 대체함
  - ⑦ 배포를 커넥니 등 다른 팀원에게 임의로 재배정하지 않음(담당은 프롬프트 머리말·README 2절이 확정함)
  - 가이드·프롬프트의 지시문·placeholder·예시 문구를 값으로 채우지 않고 그대로 복사하지 않음
  - 재질문 카운터 2회 초과 시 경로를 임의로 추정해 진행하지 않음
  - ③~⑦을 병렬 Agent 호출로 동시에 실행하지 않음(선행 산출물 필수 의존 위반)
  - 가이드·README 전문을 단계마다 반복해 다시 읽지 않음(최초 1회 또는 필요한 절만 발췌)
- 완료조건:

**③ 워크플로우 설계 위임 호출 형태(Claude Code `Agent` 도구 기준 — 다른 도구는 같은 담당·순서를 그 도구의 서브에이전트 기능으로 옮김)**
```
Agent(
  subagent_type="flonie",
  description="설계서 ③ 워크플로우 작성",
  prompt="<프롬프트지시>{prompts/03-워크플로우설계.md 전체 — 경로 치환 3종 적용:
            프로젝트정보.md 경로 · guides/... 절대경로 · {출력 루트}·output/design/}</프롬프트지시>
          <가이드점검표>{guides/03-*.md 4절 「제출 전 자가 점검표」 발췌 — ⑦만 3절임}</가이드점검표>
          <선행산출물>{01-목표품질속성카드.md·02-논리아키텍처.md 참조 절}</선행산출물>",
  run_in_background=false
)
```
`subagent_type="flonie"`가 `.claude/agents/flonie.md`의 팀원 정의를 싣고, `<프롬프트지시>` 안의
`[역할]` 절("오케스트레이션 엔지니어 플로니 · 프로파일 · 성향 · 경력 · 이 산출물을 맡는 이유")이
산출물별 세부 인격을 더함. ⑦ 배포는 같은 형태로 `subagent_type="opsni"`를 씀.
`flonie`가 사용 가능 목록에 없으면 `subagent_type="general-purpose"`로 바꾸고 나머지는 동일함.

**⑤ 완료 후 ④를 다시 호출하지 않음** — 산출물 1종당 Agent 호출은 1회임.
④에 되짚어 넣을 값이 없으므로 ④를 향한 두 번째 호출을 만들지 않음.
