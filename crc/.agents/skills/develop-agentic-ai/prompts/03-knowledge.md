# 개발 프롬프트 3 지식 경로

> 이 파일 전체를 AI 코딩 도구에 붙여 넣어 코드를 만듦. 이 문서 자체는 코드가 아님.  
> 주 입력: 설계서 ⑤ 지식/도구. **판단은 설계서가 이미 끝냈고 이 프롬프트는 옮기기만 함**  
> 실행 순서: 1 → 2 · 4 · 5(병렬) → **3** → 6 → 7 → 8 · 9(병렬)  
> 담당 인격: 지식니(지식·데이터 엔지니어)

## [목표]

담당자가 **무엇을 근거로 답하는가**를 코드로 고정하기 위하여, 설계서가 **채택한 지식 경로만**
골라 조회 계층 · 색인과 검색기 · 질의 변환과 재정렬 · 결정론 선행 필터를 만듦.

## [역할]

당신은 `AGENTS.md` design-agentic-ai 팀의 **지식·데이터 엔지니어 지식니**입니다.

- 프로파일: 노리지 / 지식니 / 여성 / 33세
- 성향: **"검색이 안 되면 모델을 바꿔도 소용없다"** — 데이터 품질과 평가셋을 먼저 봄.
  집계 질문을 문서 검색에 던지는 설계를 통과시키지 않음
- 경력: 데이터 엔지니어 8년 + 대규모 검색·지식그래프·질의 생성 시스템 5년
- 이 산출물을 맡는 이유: **"이 질문을 어떤 경로로 답할 것인가"는 단일 결정**임.
  경로가 갈리면 색인 · 검색 · 평가가 전부 갈림
- 전문 용어는 업계 표기 그대로 씀. 약어는 처음 나올 때만 원어를 괄호로 병기함
  (예: `RRF(Reciprocal Rank Fusion)` · `HNSW(Hierarchical Navigable Small World)`)

## [맥락]

- 내 상황: 공통 런타임과 데이터 준비가 끝났음. **읽을 데이터는 있고 검색기는 없음**
- 이 코드가 없으면 막히는 곳: `06-workflow.md`(담당자가 부를 검색 함수가 없음) ·
  `09-eval.md`(잴 대상이 없음)
- 이 산출물의 성격은 설계서 ① 「성격 선언」을 그대로 따름 — 사람이 최종 결정하는 산출물이면
  검색 결과는 **근거 제시**이지 확정 답이 아님
- 담당 경계 — 아래는 **만들지 않음.** 자리만 비워 두고 다른 프롬프트가 채움

| 영역 | 담당 | 이 프롬프트가 하는 일 |
|------|------|---------------------|
| 흐름 조립 · 노드 함수 | `06-workflow.md` | 검색 함수를 **내놓기만** 함. 어디에 붙일지는 안 정함 |
| 원천 접속 · 시드 데이터 | `02-dataset.md` | 그 계층을 **가져다 씀.** 다시 만들지 않음 |
| 바깥 API 도구 | `04-connector.md` | 검색 경로 안에서 바깥 API를 부르지 않음 |
| 가리기 · 검사 · 기록 | `05-guardrail.md` | 그 모듈이 끼어들 **자리(훅)만** 남겨 둠 |
| 골든셋 채점 | `09-eval.md` | 결과를 **돌려주기만** 함. 점수는 안 냄 |

- 이 산출물이 소유하는 값: 검색 함수 이름 · 후보 결과의 반환 형태 ·
  **권한 스크립트 파일 이름 · `담당자 → role` 매핑 설정의 이름·형식·기동 검증 방식**
  (담긴 **값**은 ⑤ 소유)
- 이 산출물이 소유하지 않는 값: 조회 컬럼 허용 목록(⑤ 「담당자별 허용 열」 소유) ·
  금지 컬럼(⑤ 「정형 접근 금지 컬럼」 소유) · 방식별 설정값과 **벡터DB명·그래프DB명**(⑤ 채택 방식 스펙 소유) ·
  **노드·관계 접근 필터**(⑤ 소유) · 프로세스 경계를 넘는 반환 키 이름(③ 「프로세스별 API 설계」 소유)
- 결과물 독자: 이 검색 함수를 담당자 모듈에 끼울 개발자, 결과를 평가할 사람

## [처리]

### 1단계 — 시작 조건 확인 (가장 먼저 수행)

- `개발환경정보.md`에서 `D-01` · `D-05` · `D-06` · `D-07` · `D-12`를 읽음.
  `프로젝트 확정 필요`가 하나라도 있으면 **코드를 만들지 않고** 무엇이 비었는지 적어 사용자에게 문의함
- `{출력 루트}`에 `05`가 있는지 확인함. 없으면 그것을 먼저 만들라고 보고하고 멈춤
- `02-dataset.md`가 만든 원천 접속 계층이 있는지 확인함. 없으면 **인터페이스만 가정**하고
  그 사실을 보고에 1줄 남김
- 확인 결과를 3줄 이내로 먼저 보고한 뒤 2단계로 넘어감

### 2단계 — 적용 판정 (이 프롬프트의 핵심. 설계서에서 읽음)

**⑤가 채택한 경로만 구현함. 미채택 경로는 파일 자체를 만들지 않음.**  
아래를 읽어 표로 만들어 응답에 **먼저 보임.** 사용자가 여기서 되돌릴 수 있게 함.

| 경로 종류(일반명) | 채택 여부를 어디서 읽나 | 채택이면 만드는 것 |
|-----------------|----------------------|------------------|
| 조회 | ⑤ 「정형 접근 경로」에 행이 있나 | 조회 계층 — 조건 걸기 · 정렬 · 행 수 상한 |
| 고정 쿼리 / NL2SQL | ⑤ 「정형 접근 경로」의 경로마다 적힌 방식(근거는 ③의 `모델 호출` 열) | `고정 쿼리`면 미리 박은 문장 + 파라미터, `NL2SQL`이면 변환기 + 검증 문 |
| 의미정보(RAG) | ⑤ 「경로 채택·미채택」 | 색인 만들기 + 유사도 검색기 |
| 관계정보(GraphRAG) | ⑤ 「경로 채택·미채택」 | 개체·관계 적재기 + 관계 따라가기 검색기 |
| 용어사전 | ⑤ 「경로 채택·미채택」 | `02-dataset.md`의 매핑 파일을 **아래 「용어사전 적용 지점」 표가 정한 지점에** 적용 |

- **경로 이름을 ⑤의 이름으로 부름** — `의미정보(RAG)` · `관계정보(GraphRAG)` · `용어사전`.
  다른 이름을 새로 만들지 않음
- 채택한 방식마다 ⑤ 채택 방식 스펙의 칸을 **하나도 빼지 않고** 설정으로 옮김
  (의미정보 구축 13열 + 검색 7열 · 관계정보 3파트(⑴ + 색인 · ⑵ · ⑶.
  **⑷ `합격선`은 설정이 아니라 검사라 여기서 안 셈 — 7단계가 다룸**) · 외부검색 10열 · 용어사전 ⑴ 운영 스펙 6열 + ⑵ 대표어별 동의어 ·
  Pre 4기법 · Post 4기법 · 검색 패턴별 판정 기준값).
  칸이 비어 있으면 값을 지어내지 않고 `[확인필요]`로 표에 적고 3단계에서 되물음
- **미채택 방식의 파일 · 설정 · 의존성을 만들지 않음.** "나중에 쓸지 몰라서" 만들어 두지 않음.
  만들지 않았다는 사실을 보고에 1줄 적음
- 아래를 함께 판정함

| 판정 항목 | 어디서 읽나 | 무엇이 갈리나 |
|----------|-----------|-------------|
| 조회 컬럼 허용 목록 | ⑤ 「담당자별 허용 열」 | 이 목록에 없는 열은 **조회문에 넣지 않음**. ④는 저장소 이름·등급까지만 정하므로 열은 여기서만 옴 |
| 조회 차단 목록 | ⑤ 「정형 접근 금지 컬럼」 | `표.열` 꼴 전건이 차단 목록이 되고 **위반 시 실패하는 시험**이 붙음 |
| 되돌릴 수 없는 판정이 걸리나 | ⑤ 2절 4단계 결과 — 그 필드가 **고정 쿼리 경로로만** 배정됐고 허용 열·커넥터 키에서 빠졌나 | 걸리면 **검색 앞에 결정론 선행 필터**를 두고 모델 입력에서 그 필드를 지움 |
| 노드·관계 접근 필터 | ⑤ 「관계정보(GraphRAG)」 ⑵ 접근 필터(담당자마다 1행) | `허용 노드 타입`·`허용 관계 타입`·`권한 조건`은 **그래프DB 권한 스크립트**로, `질의 조건`은 **질의 코드**로 만듦(7단계). 허용 목록을 앱 설정에 담지 않음 |
| 적재 합격선 | ⑤ 「관계정보(GraphRAG)」 ⑷ 적재 스펙의 `합격선` · `불합격 시 처리`(**주인은 ⑤**) | 적재할 때 거는 검사로 만듦(7단계). **새 기준을 여기서 정하지 않음** |

**용어사전 적용 지점** — ⑤는 시점을 정하지 않음(소비처가 정함). **아래 표대로 고정하고 되묻지 않음**:
소비처마다 지점이 이미 결정적이라 고르게 하면 돌릴 때마다 다른 코드가 나옴.

| 소비처 | 적용 지점 | 쓸 수 있는 `1:N 충돌 처리` |
|-------|---------|------------------------|
| 정형 코드 정규화 | 질의를 SQL·파라미터로 바꾸기 **직전** | `둘 다 확장`을 **못 씀**(코드 값이 1개여야 함) |
| 의미정보 질의 확장 | 임베딩 만들기 **직전** | 4지 모두 |
| 관계정보 ⑷ 동일 개체 판별 | 노드 만들기 **직전**(적재 시) | `둘 다 확장`을 **못 씀** |
| 관계정보 ⑶ 하위개념 정규화 | ⑤ ⑶ 「개념 계층」의 `적용 시점` 칸이 정한 시점 | 그 칸은 ⑤에 남아 있으므로 여기서 정하지 않음 |

- **⑤ `1:N 충돌 처리`가 `둘 다 확장`인데 정형 코드 정규화·동일 개체 판별에 그 사전을 쓰면
  코드를 만들지 않고 `[확인필요]`로 표에 적고 3단계에서 되물음** — 값이 1개여야 하는 자리에
  두 개가 들어오면 조용히 틀림
- **사전을 벡터DB에 올려 유사도로 찾게 만들지 않음**: 정확 일치가 먼저이고,
  ⑤ `미등록어 처리`가 `유사도 후보 제시`일 때만 폴백으로 유사도를 씀.
  그때도 **자동 확정하지 않고** 후보로만 쓰고 기록을 남김

### 3단계 — 되묻기 (답을 받기 전에는 코드를 만들지 않음)

⑤와 ④의 **「미확정 항목」 부속 표에 있는 `[확인필요]` 행을 먼저 목록으로 옮긴 뒤**,  
아래를 기본값과 함께 물음. 사용자가 `기본값으로 진행`이라 하면 되묻지 않고 진행함.

| 물을 것 | 기본값 제시 | 왜 묻나 |
|--------|-----------|--------|
| 색인을 다시 만들 때 기존 것을 지우나 새로 만들어 갈아 끼우나 | 새 이름으로 만들고 다 되면 갈아 끼움 | ⑤ 벡터DB 스펙은 벡터DB명·문서 범위·기준일까지만 정함. 다시 만드는 절차가 없음 |
| 결과가 0건이거나 점수가 낮을 때의 착지 | 빈 결과 + 사유를 돌려줌 — **모른다고 답하게 함** | 억지로 채운 근거가 그대로 답이 됨 |
| 경로를 2개 이상 쓸 때 합치는 규칙 | 경로별로 따로 돌려주고 합치지 않음 | 합치는 규칙이 ⑤에 없음. 임의로 섞으면 근거 출처가 흐려짐 |
| 검색 결과를 잠시 저장해 둘지, 얼마나 둘지 | 저장하지 않음 | 저장하면 원본이 바뀌어도 옛 답이 나감 |
| 낮은 점수를 가르는 문턱을 무엇으로 두나 | 점수 문턱 대신 **후보 수 0건**을 신호로 씀 | ⑤에 문턱이 없을 때 숫자를 지어내지 않기 위함 |
| 코드 정규화·동일 개체 판별에 쓸 `1:N 충돌 처리` | `보류·경고` — 정규화하지 않고 원문을 두고 기록에 남김 | ⑤가 `둘 다 확장`으로 정했는데 값이 1개여야 하는 자리에 그 사전을 씀. 두 개가 들어오면 조용히 틀림 |

- 되묻기로 정한 값은 **설계서 ⑤에 되돌려 적을 것**을 응답에 1줄로 권고함(값의 주인이 ⑤이므로)

### 4단계 — 결정론 선행 필터를 만듦 (2단계에서 걸린 항목만)

- **되돌릴 수 없는 판정에 쓰이는 필드는 검색보다 먼저** 규칙으로 거름.
  확률로 답하는 경로(NL2SQL · 의미정보 · 관계정보)에 그 판정을 맡기지 않음 —
  ⑤ 2절 4단계가 이미 그 필드를 고정 쿼리 경로로만 배정해 뒀음
- 필터는 **입력 → 통과·차단 → 사유** 3가지만 돌려주는 순수 함수로 만듦. 모델을 부르지 않음
- **모델에 넘기는 입력 규격에서 그 필드를 아예 지움.** 칸이 없으면 값이 갈 길이 없음.
  "안 쓴다"고 주석만 달아 두지 않음
- 필터를 지나가지 못한 요청은 검색기를 **부르지 않고** 그대로 착지함
- 이 필터가 필요 없다고 판정됐으면 만들지 않음. 만들지 않았다고 보고함
- **결정론 검증 단계를 새로 만들지 않음** — 단계를 늘릴 수 있는 것은 ③뿐이므로,
  단계가 필요하면 ③에 `변경요청` 1행을 남길 것을 응답에 적음

### 5단계 — 조회 계층을 만듦 (조회 경로 채택일 때만)

- ⑤ 「정형 접근 경로」의 행마다 조회 함수 1개를 만듦. `02-dataset.md`의 접속 계층을 가져다 씀
- **⑤ 「담당자별 허용 열」에 없는 열을 조회문에 넣지 않음.** 허용 목록을 상수 1벌로 둠
- ⑤ 「정형 접근 금지 컬럼」의 `표.열` 전건을 차단 목록 상수 1벌로 둠.
  차단 목록에 걸리면 **조회를 만들다 말고 실패**하게 함. 값을 가려서 내보내지 않음
- 행 수 상한을 호출마다 강제로 붙임. 상한 값은 ⑤에서 읽고 코드에 숫자로 박지 않음
- **읽기 전용만 만듦.** 넣기 · 바꾸기 · 지우기 구문을 이 계층에 두지 않음

### 6단계 — NL2SQL 경로를 만듦 (⑤가 그 경로를 `NL2SQL`로 적었을 때만)

- 자연어를 조회문으로 바꾸는 변환기를 만듦. 모델은 `01-runtime.md`의 어댑터로만 부름
- **만들어진 조회문을 실행하기 전에 검사함.** 아래를 전부 통과해야 실행함

| 검사 | 통과 조건 |
|------|----------|
| 구문 종류 | 읽기 구문 1개뿐임. 넣기 · 바꾸기 · 지우기 · 구조 변경이 **0건** |
| 대상 표 | ⑤ 「정형 접근 경로」에 있는 표만 씀 |
| 열 | ⑤ 「담당자별 허용 열」 안에 있고 ⑤ 금지 컬럼이 **0건** |
| 행 수 상한 | 상한 구문이 붙어 있음. 없으면 붙여서 실행함 |
| 문장 수 | 1문장임. 이어 붙인 문장이 **0건** |

- 검사에 걸리면 실행하지 않고 사유를 돌려줌. 고쳐서 억지로 실행하지 않음
- 스키마는 **허용된 표와 열만** 모델에 보여 줌. 전체 구조를 통째로 넣지 않음

### 7단계 — 비정형 경로를 만듦 (채택한 방식만)

- 방식마다 ⑤ 채택 방식 스펙의 칸을 설정으로 옮김. **숫자를 코드에 박지 않음**

| 채택 방식 | 옮길 스펙 칸(⑤가 이름을 가짐) |
|----------|---------------------------|
| 의미정보(RAG) — 구축 13열 | 벡터DB명 · **제품·계열** · **색인 파라미터** · 소스문서 · 건수 · 기준일 · **추출** · **정제** · 청크 크기 · 중첩 크기 · 구분자 · 임베딩 모델 · 차원 수 |
| 의미정보(RAG) — 검색 7열 | 벡터DB명 · **검색 기법**(유사도·BM25·하이브리드) · **융합 방식** · **융합 파라미터** · **다양성 전략**(없음·mmr) · top-k · **후보 수**(제품이 부르는 이름 병기) |
| 관계정보 ⑴ 그래프 스펙 — 8항목(그래프DB마다 표 1개. 이름은 표 제목) | **제품** · **버전** · 타입 도출 방법 · 노드 타입 · 관계 타입(`(:출발 노드 타입)-[:관계 타입]->(:도착 노드 타입)` 꼴) · 상충 관계 쌍 · 최대 홉 수 · 결과 상한 |
| 관계정보 ⑴-1 노드 고유키 — 4열(그래프DB마다 표 1개. 노드 타입 1개 = 행 1개) | 노드 타입 · 키(복합 키는 순서까지) · **제약 종류**(`IS UNIQUE`·`IS NODE KEY`·`없음`) · 이유. **표 전체가 `확정값`임** |
| 관계정보 ⑴-2 관계 사용 단계 — 3열(관계 타입 × 단계 = 행 1개) | 관계 타입 · **워크플로우**(`ID. 이름`) · **단계**(`ID. 이름`. 이름은 ③ 「단계별 설계」의 `행동 1개` 값 그대로). ⑴ `관계 타입` 전건이 1행 이상 있어야 함 |
| 관계정보 ⑴-3 색인 — 5열(그래프DB마다 표 1개. 인덱스 1개 = 행 1개) | 대상(`:라벨(속성)`·`[:관계타입](속성)`) · 종류 · **사용 워크플로우**(`ID. 이름`) · **사용 단계**(`ID. 이름`. 그 인덱스를 출발점으로 쓰는 단계) · 의미. **표 전체가 `초기값`임** |
| 관계정보 ⑵ 접근 필터 — 6열 | 담당자(`ID. 이름`) · **역할명**(그래프DB role) · 허용 노드 타입 · 허용 관계 타입 · **권한 조건**(`(:노드 타입).속성 비교 값` — role 권한이라 질의와 무관하게 늘 적용) · **질의 조건**(`(:노드 타입).속성 비교 ③ State 필드` — 앱이 질의에 추가) |
| 관계정보 ⑶ 개념 계층 — 4열 | 상위개념 · 하위개념 · **적용 시점** · **관계 타입**(`적재 시`일 때만. ⑴에 있는 것만). 안 쓰면 `해당 없음` |
| 외부검색(웹·영상) — 10열 | 검색 대상 · 도구 · **커넥터 ID `C-A*`** · 기간 지정 · 정렬 지정 · 결과 수 상한 · **본문 추출 도구** · **출처 표기** · **캐시 저장소**(`메모리`·`Redis`) · 캐시 유효기간 |
| 질의 전처리(Pre) — 4기법 6열 | Rewriting · Multi-Query · HyDE · Step-Back. 기법마다 `사용여부` · `사용 경로` · `사용/미사용 이유` · `적용 방법` · `모델 호출` |
| 결과 후처리(Post) — 4기법 6열 | 리랭킹 · Filtering · Compression · Fusion. 기법마다 `사용여부` · `사용 경로` · `사용/미사용 이유` · `적용 방법` · `모델 호출` |
| 용어사전 — ⑴ 운영 스펙 6열 | **`사전 이름`**(파일명·Redis 키가 여기서 나옴) · `저장 위치`(`파일`·`Redis`) · `형식`(`Redis`면 `Hash` 고정) · `1:N 충돌 처리`(4지) · `미등록어 처리`(4지) · `갱신 주기` |
| 용어사전 — ⑵ 대표어별 동의어 2열 | `대표어` · `동의어`. **대표어 1개 = 1행.** 적용 시점·표기·얹는 경로는 ⑤에 없음(위 「용어사전 적용 지점」 표가 정함) |

- **색인 만들기와 검색기를 짝으로 만듦.** 색인을 만든 설정과 검색할 때 쓰는 설정이 같은 곳에서 나오게 함
- 색인에는 **어느 문서의 어느 자리에서 왔는지**를 함께 넣음. 근거를 되짚을 수 없는 결과를 만들지 않음
- 관계정보는 **최대 홉 수와 결과 상한을 반드시 걺**. 접근 필터는 아래 권한 스크립트가 맡음
- **⑵ 접근 필터는 앱이 검사하지 않고 그래프DB 권한으로 막음**: ⑤ ⑵의 행마다
  `허용 노드 타입`·`허용 관계 타입`·`권한 조건`을 그 `역할명` role에 부여하는
  **권한 스크립트 1벌**을 만듦. 허용 목록을 코드나 앱 설정에 담지 않음
  - **스크립트를 만들기만 하고 앱이 실행하지 않음**: role을 만들려면 관리자 권한이 필요한데
    앱에 그 권한을 주면 최소 권한이 깨짐. **실행은 배포·운영이 하고 `08-deploy.md`가 배포 절차에 실음**
  - **앱이 그 role로 접속하는 방법은 설계 범위 밖임**(⑤ ⑵ `역할명` 칸이 그렇게 정함):
    ⑦ 배포도 접속정보를 갖지 않으므로 `[확인필요: role 접속 방식]`으로 두고
    **접속 계층을 갈아 끼울 수 있게** 만든 뒤 접속 자격은 환경변수로 뺌
  - **기동할 때 그 role로 붙었는지 확인하고 아니면 뜨지 않게 함**: 서비스 계정으로 붙은 채
    돌면 허용 목록이 통째로 무의미해지는데 **오류가 안 나서 안 드러남**
  - **`담당자 → role 이름` 매핑만 앱 설정으로 둠**: ⑤ ⑵의 `담당자`·`역할명` 두 칸에서 옮김.
    비밀값이 아니므로 일반 설정으로 배포함. **허용 목록은 여기 담지 않음**
  - 기동할 때 ⑤ ⑵의 담당자와 이 매핑이 **1:1인지 확인하고 어긋나면 뜨지 않게 함**
- **`질의 조건`은 권한으로 못 막으므로 질의 코드가 검**: ⑤ ⑵ `질의 조건`이 가리키는
  ③ State 필드에서 값을 꺼내 **파라미터로 바인딩**함. 값을 코드에 박거나 기본값으로 채우지 않음.
  **빼먹으면 아무 오류 없이 조건이 풀리므로** 시험으로 확인함
- **부정 관계**(`제외함` 같은 것)를 ⑤가 정의한 대로 별도 관계 타입으로 만듦.
  긍정 관계와 한 선으로 합치면 못 먹는 것을 추천하는 정반대 결과가 나옴
- **⑷ 「적재 스펙」의 `합격선`을 적재 검사로 구현함.** 통과하지 못하면 같은 행의
  ⑤ `불합격 시 처리` 칸이 적은 대로 처리함. 기준값과 처리 방식을 개발이 새로 정하지 않음(⑤ 소유)
  - **`상충 관계 쌍`은 비율 조건과 성격이 다름**: 정확도 90%처럼 비율로 보는 것이 아니라,
    그 쌍이 같은 출발·도착 짝에 **동시에 붙으면 1건이라도 불합격**임.
    두 조건을 **한 검사로 뭉치지 않음** — 비율 검사와 따로 둠
  - 왜 거르나: 상충 쌍이 동시에 붙으면 홉을 따라가는 쪽에서 구별이 안 되어 **못 먹는 것을
    추천하는 식으로 정반대 답이 나감.** 질의 시점에는 못 잡으므로 적재 시점에 잡음
- 임베딩 모델 이름 · 색인 제품 이름을 코드에 박지 않음. 전부 설정으로 주입함
- 용어사전은 `02-dataset.md`가 만든 매핑 파일을 읽어 **위 「용어사전 적용 지점」 표가 정한
  지점에서만** 씀. 사전을 다시 만들지 않음
- **검색 계층이 대표어로 표기를 통일하지 않음**: 원문과 대표어를 **함께** 돌려줌.
  둘 다 들고 있으면 화면이 뒤에서 고를 수 있고, 한쪽만 돌려주면 되돌릴 수 없음.
  화면에 무엇을 보일지는 이 프롬프트가 정하지 않음

### 8단계 — 질의 변환과 재정렬을 만듦 (⑤에 스펙이 있을 때만)

- 질의 변환(질문을 검색하기 좋은 말로 바꾸기)은 **⑤ 「질의 전처리(Pre)」의 `사용여부`가 `사용`인
  기법만** 만듦. 기법마다 `얹는 경로`·`적용 방법`을 그대로 옮김. `미사용` 기법은 만들지 않음
- 재정렬(뽑아온 후보를 다시 줄 세우기)은 ⑤ 벡터DB 스펙의 `리랭킹 모델`이 `해당 없음`이 아닐 때만 만듦.
  값이 비었으면 만들지 않고 `[확인필요]`로 남김
- 재정렬 모델 이름 · 가중치를 코드에 박지 않음. 전부 설정으로 뺌
- 변환 전후의 질의와 재정렬 전후의 순위를 **기록으로 남길 자리**를 둠.
  실제 기록은 `05-guardrail.md`가 끼움

### 9단계 — 결과 반환 형태와 실패 착지를 만듦

- 검색 함수는 결과마다 **내용 · 출처 · 점수** 3가지를 함께 돌려줌. 출처 없는 결과를 돌려주지 않음
- 후보가 0건이거나 3단계에서 정한 착지 조건에 걸리면 **빈 결과 + 사유**를 돌려줌.
  없는 근거를 만들어 채우지 않음
- 반환 키 이름은 ③ 「State 구조」의 필드 이름을 그대로 씀. 프로세스 경계를 넘겨 돌려주는 값이면
